# Stage 4 rubric: Capstone Production

| Level | Build checklist | Build quality | Documentation | Process |
| --- | --- | --- | --- | --- |
| **Not yet** | No checklist, or tasks too large to track | Console errors, or missing keyboard routes | README does not let a stranger run the project | Changelog absent or clearly written retroactively |
| **Meets expectations** | Small, ordered, checkable tasks, all completed or explicitly cut | Passes accessibility and performance checks from Stage 2's plan | README, user guide, and changelog all present and specific | Mid-build review happened and regressions were fixed |
| **Strong** | Tasks grouped by area, progress visible throughout | Regularly re-tested during the build, not only at the end | README verified against a genuinely fresh setup (Challenge 1) | Cuts from Stage 1 scope are documented with reasons |
| **Exceptional** | Checklist reflects real, ongoing prioritisation decisions | A basic automated check exists and is documented (Challenge 3) | Includes a detail reflecting the builder's own language or community (Challenge 2) | Changelog and case-study material are already well prepared for Stage 5 |

This stage is approved when the production build passes its own quality checklist and a stranger could set it up from the README alone.
