# 测试、发布与展示

**Language / Idioma / 语言:** [English](README.md) · [Español](README.es.md) · [简体中文](README.zh-Hans.md)

**课程：** `capstone` · **课时：** `testing-launch-and-presentation-05` · **时长：** 约 12 小时 · 16 次学习，每次 45 分钟 · 每周 4 次，约 4 周

---

> 发布毕业设计、公开仓库、案例分析和展示演讲。

---

## 学习目标

完成本项目后，你将能够：

1. 对无障碍性、性能和功能，进行一次最终的发布测试。
2. 发布一个带有清晰、诚实的 README 的公开代码仓库。
3. 撰写一份案例分析，解释你构建了什么、为什么，以及你学到了什么。
4. 为非技术受众准备一场关于你毕业设计的简短展示。
5. 对你自己五个阶段的整个过程进行一次复盘。
6. 为这个项目在 XR Camp 之后找到一个真实或合理设想的下一步。
7. 带着来自第一到四阶段的证据支撑，自信地展示你完成的作品。

## 先决条件

- **第 7.4 阶段：毕业设计生产构建。** 在开始这个阶段之前，你需要有一个已获批准、经过测试的生产构建。

## 你将构建什么

专业毕业设计的第五阶段，也是最后一个阶段：公开**发布**你的毕业设计，撰写一份**案例分析**，准备一场**展示演讲**，并对整个五阶段过程进行一次**复盘**。

[`completed/`](completed/) 中的参考答案，是 Ana 为 Aurora 社区博物馆展览——这门课程贯穿全部五个阶段所跟随的那个毕业设计——填好的发布检查清单、案例分析、展示大纲和复盘记录。[`completed/index.html`](completed/index.html) 把这四者都呈现了出来，并附上链接回到之前每一个阶段。起始代码有同样的四份模板，一共 8 个 TODO，还有这个阶段的评分标准。

## 分步讲解

### 规划你的学习节奏

| 节次 | 你要做的事 | 完成后你将拥有 |
| --- | --- | --- |
| 1 | 环境配置；把你第一到四阶段的文档收集到一处 | 撰写案例分析所需的一切，随手可取 |
| 2 | 第 1 步：发布检查清单，第一部分（TODO 1） | 一份涵盖无障碍性、性能和功能的最终测试计划 |
| 3 | 第 1 步，续（TODO 2） | 发布步骤：仓库、README、许可证、可访问的链接 |
| 4-5 | 进行最终测试 | 发布检查清单上的每一项都已核对，任何问题都已修复 |
| 6 | 发布公开仓库 | 一个公开、能正常运作的仓库链接 |
| 7 | 第 2 步：案例分析，第一部分（TODO 3） | 一段清晰陈述问题以及它是为谁而做的文字 |
| 8 | 第 2 步，续（TODO 4） | 你构建了什么，以及你刻意省略了什么 |
| 9 | 第 2 步，续（TODO 5） | 你学到了什么，包括至少一次诚实的挣扎 |
| 10 | 第 3 步：展示大纲，第一部分（TODO 6） | 一份面向非技术受众的简短展示结构 |
| 11 | 第 3 步，续（TODO 7） | 幻灯片或讲稿，至少大声练习过一次 |
| 12 | 第 4 步：复盘（TODO 8） | 一次回顾全部五个阶段的总结：什么发生了变化，你会怎样做得不同 |
| 13 | 向导师、同学或一个小组展示 | 一次真实展示中记录下来的反馈 |
| 14 | [`tests/checklist.md`](tests/checklist.md)；修复它发现的任何问题 | 一次准备好接受最终签字确认的发布 |
| 15 | 请求最终的导师批准 | 一个已获批准并已发布的毕业设计 |
| 16 | 一个拓展挑战，然后是**提交作业** | 一份完成的专业毕业设计 |

### 第 1 步：发布检查清单（TODO 1-2）

打开 [`starter/release-checklist.md`](starter/release-checklist.md)。列出你在发布前将最后运行一次的每一项测试（TODO 1）——把之前每个阶段用过的同样的无障碍性和性能检查，再针对完成的构建跑一遍——以及每一个发布步骤（TODO 2）：一个公开仓库、一份清晰的 README、一份许可证文件，以及一个能正常运作的可访问链接。

### 第 2 步：案例分析（TODO 3-5）

打开 [`starter/case-study.md`](starter/case-study.md)。写出问题和受众（TODO 3，直接取材于你第一阶段的简报）、你构建了什么以及你刻意省略了什么（TODO 4，取材于你第一阶段的范围和第四阶段的变更日志），以及你学到了什么（TODO 5）——包括至少一次诚实的挣扎，而不只是成功。一份只罗列成功的案例分析，读起来像营销文案，而不是真实工作的证据。

### 第 3 步：展示大纲（TODO 6-7）

打开 [`starter/presentation-outline.md`](starter/presentation-outline.md)。为非技术受众规划一场简短的展示（通常五到七分钟）：问题、一次演示或几张截图、你学到了什么，以及接下来会怎样（TODO 6）。然后准备好你真正要用的幻灯片或讲稿，并在正式展示之前，至少大声练习一次（TODO 7）。

### 第 4 步：复盘（TODO 8）

打开 [`starter/retrospective.md`](starter/retrospective.md)。回顾全部五个阶段：哪些地方花的时间比计划的更长，你导师的反馈改变了什么，以及如果今天重新开始一个新的毕业设计，你会做出哪些不同的选择。要具体——「更好地沟通」教给你的东西，远不如「我应该在第三阶段之前而不是之后，把我的线框图给一位真实用户看」那么多。

## 关键代码解析

- **发布检查清单。** 把一个完成的构建变成一个已发布项目的最终、一次性的测试和发布步骤。
- **案例分析。** 一份书面记录，说明你构建了什么、为什么，以及你学到了什么——是关于你过程的证据，而不只是你的结果。
- **展示大纲。** 一份简短、结构化的计划，用来向那些没有参与你构建过程的人解释你的工作。
- **复盘。** 一次有意识、诚实地回顾自己过程的活动，着眼于下一次你会做出哪些不同的选择。
- **公开仓库。** 你毕业设计的代码，发布在别人能够阅读、运行并从中学习的地方，遵循本仓库已经使用的许可证。

## 3D 与 XR 无障碍

针对你已发布的构建，最后再完整地跑一遍 `docs/en/xr-accessibility.md` 中的人工 3D/XR 无障碍检查清单：场景描述、键盘路径、减少动态效果、2D 后备方案，以及舒适度。这是在链接出现在你的案例分析和展示中、公开传播出去之前，捕获一次回归问题的最后机会。

## 无障碍要求

| 要求 | WCAG 2.2 | 原因 |
| --- | --- | --- |
| 已发布仓库的 README 清楚地说明了许可证 | 良好实践 | 任何重用或学习这份代码的人，都需要知道它的条款 |
| 最终发布再一次通过了第二到四阶段的每一项无障碍检查 | 多项（见前面各阶段） | 在第四阶段后期引入的回归问题，绝不能带入公开发布 |
| `completed/index.html` 声明了 `lang="en"` | 3.1.1 页面语言 | 辅助技术需要知道该应用哪种语言规则 |
| 展示幻灯片或讲稿使用可读的对比度和通俗的语言 | 1.4.3、良好实践 | 一次展示同样是一份面向公众的文档 |

## 性能注意事项

在发布可访问的链接之前，针对你第二阶段的预算，做最后一次性能测量。一个在第四阶段还在预算之内的毕业设计，如果之后又有所膨胀（一个被遗忘的调试功能、一个未经优化的素材），应该在这里被发现，而不是等它的第一位真实访客来发现。

## 常见错误

| 错误 | 会发生什么 | 应该怎么做 |
| --- | --- | --- |
| 没有做最终测试就发布 | 第四阶段后期出现的一次回归问题，会波及真实访客 | 在发布之前，再完整地跑一遍发布检查清单 |
| 撰写一份没有任何诚实挣扎的案例分析 | 读起来像营销文案，也错失了展示真实学习成果的机会 | 至少包含一次真实的困难，以及你是如何应对的 |
| 没有大声练习就去展示 | 展示会超时，或者遗漏关键要点 | 至少练习一次，最好是说给另一个人听 |
| 因为项目「已经完成」而跳过复盘 | 同样可以避免的错误，会在下一个项目中重演 | 写下具体、可执行的记录——复盘是为了你的下一个毕业设计，而不只是这一个 |
| 一个没有 README 或许可证的公开仓库 | 没有人能理解或重用这份工作 | 遵循本仓库自己的模式，把两者都发布出来 |

## 故障排查

**我不确定案例分析的「我学到了什么」这一节该写什么。** 看看你第三、四阶段的变更日志和设计评审记录：最诚实的学习成果，往往最先出现在那里，以一次你不得不做的修复的形式。

**我的展示时间超了。** 削减细节，而不是结构：保留问题、演示、一项诚实的学习成果和下一步计划，把剩下的细节移到案例分析里去。

**我没有一个真实的项目下一步计划。** 一个现实、适度的下一步——「添加西班牙语和中文翻译」「找五位真实用户测试」——就足够了。它不需要是一个有把握的计划。

## 拓展挑战

三个拓展挑战，位于 [`challenges/`](challenges/)。基础挑战为必做，另外两个为选做：

1. **[基础](challenges/challenge-1.zh-Hans.md)**：向一位从未见过你毕业设计的人展示它，计时，并记录下他们事后提出的问题。
2. **[创意](challenges/challenge-2.zh-Hans.md)**：把你案例分析的开篇段落，写得清楚地体现出你自己的声音、语言背景或社区，而不是一种泛泛的模板腔调。
3. **[探索](challenges/challenge-3.zh-Hans.md)**：写一份简短的「如果我还有一个阶段」计划：你接下来会构建的、最有价值的一件事，以及你为什么选择它而不是其他选项。

## 提交作业

1. 完成 [`tests/checklist.md`](tests/checklist.md)。
2. 拍摄你已发布的公开仓库和展示标题页的截图。
3. 把你的发布检查清单、案例分析、展示大纲和复盘记录，保存在你的学习日志和作品集中。也可以和其他开发者分享它们（参见[在哪里分享你的作品](../../docs/en/community.md)，英文）——这是你毕业设计的公开记录。
4. 学习日志问题：回顾全部五个阶段，你最引以为豪的一个决定是什么？你会做出不同选择的又是哪一个？

## 标准聚焦

为你的公开仓库选择一份开源许可证（本课程自己也使用了独立的代码和内容许可证，分别在 `LICENSE-CODE` 和 `LICENSE-CONTENT` 中），是一个值得慎重对待、与标准相关的决定：开源促进会（Open Source Initiative）维护着大多数自由许可证所依据的定义，所以一个已发布的毕业设计，应该清楚地说明自己的许可证，而不是把它悬而未决。
