# Project check

Work through this list before you submit.

## Release
- [ ] The full release checklist (accessibility, performance, function) was run once more on the final build.
- [ ] The public repository is live, with a clear README and a stated licence.
- [ ] The live link works when opened in a fresh, unauthenticated browser session.

## Case study
- [ ] The problem and audience are stated clearly, matching the Stage 1 brief.
- [ ] What was built, and what was deliberately left out, are both named.
- [ ] At least one honest struggle is included, not only successes.

## Presentation
- [ ] The presentation was given to a real audience at least once (Challenge 1 or otherwise).
- [ ] It fits its planned time.
- [ ] It includes a demonstration or screenshots, not only description.

## Retrospective
- [ ] Specific, actionable notes exist on what would be done differently next time.
- [ ] The retrospective covers all five stages, not only the most recent one.

## Quality
- [ ] The browser console has no errors on any released page.
- [ ] Mentor approval is recorded as the final step.

## 3D and XR (manual)

Automated tools cannot see inside a 3D canvas, so these are checked by a person. See [`docs/en/xr-accessibility.md`](../../../docs/en/xr-accessibility.md).

- [ ] The final release still passes a scene-description, keyboard, reduced-motion, 2D-fallback, and comfort check.
- [ ] Nothing in the released build regressed since Stage 4's approval.
