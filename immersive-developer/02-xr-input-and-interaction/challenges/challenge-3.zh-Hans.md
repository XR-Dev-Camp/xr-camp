# 挑战 3：探索

**进阶选做。** 约 90 分钟。

支持仅凭凝视的输入方式，并比较 three.js 的占位手部模型和它真实的手部模型。

## 任务

1. 为 `targetRayMode === 'gaze'` 的输入源（完全没有按钮的 cardboard 式头显）添加停留时间选择功能：在 `controllers.js` 中，追踪一条凝视射线连续命中同一个菜单按钮多长时间（使用 `renderer.xr` 自己的逐帧更新，或者 `app.onXRFrame`），大约连续 1.5 秒后，自动触发该按钮的操作，方式和 `onSelectStart` 处理一次真实的 select 事件相同。随着停留时间推进，在按钮上显示一个逐渐填满的高亮效果，让凝视用户也能获得和控制器闪烁一样的视觉反馈。
2. 在 `buildHandModel()` 中，尝试给 `handModelFactory.createHandModel()` 传入 `'boxes'` 或 `'spheres'`，而不是 `'mesh'`。比较一下：哪种加载更快？哪种看起来更好？以及这是否会改变指向菜单的难易程度。
3. 阅读 three.js 的 `XRHandModelFactory.js` 源码（如果你安装过，就在 `node_modules` 中查看，否则在 GitHub 上查看，固定到 r186 版本），读到足以用你自己的话解释：`'mesh'` 和 `'boxes'` 到底有什么不同的做法。

## 为什么这很重要

仅凭凝视的头显确实存在，而且往往是价格最低的那一类：只为控制器和手设计，会把真实的学习者排除在外。阅读一个库真实的源代码，而不是靠名字猜测，也是这门课程反复回到的一项技能（参见 4.1 的探索挑战）。

## 完成标准

- [ ] 一个凝视输入源（`targetRayMode === 'gaze'`）能够通过停留在一个菜单按钮上来选择它，并在停留期间显示一个可见的填充式高亮效果。
- [ ] 手部模型可以切换为 `'boxes'` 或 `'spheres'`，并且你能说出发生了什么变化。
- [ ] 你能用一两句话解释，`XRHandModelFactory` 的 `'mesh'` 选项做了哪些 `'boxes'` 没有做的事。
