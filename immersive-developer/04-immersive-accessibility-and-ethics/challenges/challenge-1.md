# Challenge 1: Foundation

**Required.** Roughly 45 minutes.

Audit and fix one more accessibility problem this lesson did not cover, and add it to your own audit table.

## Task

1. Pick one real-world XR accessibility problem that this lesson's starter did not include - for example: colour-only status indicators (XAUR User Need 6, colour-blind users needing customisable colours), no way to check where you are after magnifying part of the view (XAUR User Need 7), or interactions that move too fast to keep up with (XAUR User Need 15).
2. Add the problem to `completed/index.html` and its scripts deliberately, the same way this lesson's starter does - a small, clearly commented regression.
3. Fix it, with a comment explaining what you changed and why.
4. Add one row to your own audit table (from README.md session 13) for this new fix, citing the XAUR user need it answers.

## Why this matters

The 19 XAUR user needs in this lesson's audit are not an exhaustive list of every problem you fixed - they are a sample. Practising the same audit-then-fix method on a problem nobody handed you is what makes it a transferable skill rather than a memorised checklist.

## Done when

- [ ] A new, clearly commented accessibility problem exists somewhere in your own copy of the scene, and is then fixed.
- [ ] Your audit table has a new row citing the specific XAUR user need (or WCAG 2.2 success criterion) it answers.
- [ ] `node scripts/validate-projects.mjs` still passes.
