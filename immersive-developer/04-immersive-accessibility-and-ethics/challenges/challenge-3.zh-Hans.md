# 挑战 3：探索

**进阶选做。** 约 90 分钟。

比一份固定的逐字稿走得更远：尝试实时的真实字幕，或一位真实的第二参与者。

## 任务

任选其一：

- **实时字幕。** 使用 Web Speech API 的 `SpeechRecognition`（在你的浏览器支持它的地方——它并非普遍支持，所以要做特性检测，并保留固定逐字稿作为后备方案），为学习者自己说出的「问题」生成字幕，而不只是为讲解者固定的台词生成字幕。把识别出的文字显示在本课已经搭建好的同一个 `#captions` 元素中。
- **一位真实的第二参与者。** 只使用免费工具（例如，通过一种免费的信令方式实现的 WebRTC 数据通道，或者在同一设备上的两个标签页之间，用 [BroadcastChannel API](https://developer.mozilla.org/en-US/docs/Web/API/BroadcastChannel)（英文）共享的浏览器标签页，用于测试），用一个真实的第二个连接来替换被模拟的访客，同时保留本课已经搭建好的个人空间半径、静音和屏蔽控件。

## 为什么这很重要

本课的访客和字幕是刻意简化的替代品，在 `audit.md` 中已经明确说明了这一点，因为 XR Camp 没有付费的多人在线后端可以依托。真实的共享 XR 体验需要本课搭建的一切——个人空间、静音、屏蔽、知情同意——才能应对一个真实的、可能难以预测的另一个人。这个挑战是迈向那个更难问题的第一小步。

## 完成标准

- [ ] 上面两个选项中的一个，只使用免费工具，端到端地正常工作。
- [ ] 个人空间半径、静音和屏蔽控件（如果你选择了第二个选项）在真实连接下依然能用。
- [ ] 你的代码中有一条注释，说明你使用了哪个免费工具，以及它有什么限制（例如，`BroadcastChannel` 只能在同一设备的标签页之间工作，无法跨越互联网）。
