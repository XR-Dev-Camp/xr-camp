# 沉浸式无障碍与伦理

## 学习目标

完成本项目后，你将能够：

1. 在一个可运行的 XR 场景中，识别出「只是能渲染出来」和「一位残障学习者真的能使用」之间的区别。
2. 解释什么是 W3C 工作组说明（Group Note），它和 W3C 推荐标准（Recommendation）有什么不同，并准确引用 XR 无障碍用户需求（XAUR），包括它涵盖了什么、没有涵盖什么。
3. 修复被锚定在 3D 世界空间中的字幕，让它无论学习者在头显中还是在屏幕上看向哪里，都能保持可读。
4. 为语音内容提供完整的非音频、非 XR 替代方式，并为只存在于 3D 场景中的内容提供完整的 2D 后备方案。
5. 把一个可交互控件放到坐姿下单手可舒适触及的范围内，并为它提供一条键盘路径。
6. 分清「强制的相机运动」（绝不可接受）和「只需要一次减少动态效果检测和一个暂停控件的动画」之间的区别。
7. 在打开摄像头或其他传感器之前，先从一次真实的用户手势中征得同意，并用平实的语言说明这个传感器可能会揭示什么。
8. 为一个共享的 XR 空间设置一个个人空间边界，以及一种静音或屏蔽其他参与者的方式。

## 你将构建什么

一场简短的 XR 展览讲解：一位讲解者、来自之前课程的三件展品、语音旁白、一位来访的虚拟形象，以及一个可选的、基于摄像头的「个性化」功能。[`starter/`](starter/) 版本是**刻意做坏的**——它运行时不会报错，但会让残障学习者无法使用，并且在隐私和舒适度上有意地越界，为的是让你去发现真实存在的问题。你的任务是根据 W3C 的 XR 无障碍用户需求（XAUR）和 WCAG 2.2 对它做一次审查，然后修复你发现的问题。参考答案在 [`completed/`](completed/) 中，还附有 [`completed/audit.md`](completed/audit.md)：一份完整的审查报告，把每一处修复都对应到它所回答的确切 XAUR 用户需求或 WCAG 成功标准，其中包括三处 XAUR 完全没有涵盖的修复。`starter/js/` 中一共分布着 10 个编号的 TODO。

### 第 1 步：把这个场景当作一次审查来读，而不是一份 bug 清单（TODO 1、3、6）

本课的三个问题其实都是同一个问题的不同版本：*如果这位学习者看不到 3D 画布，或听不到音频，或无法看向字幕恰好出现的地方，他们还能获得内容吗？*`starter/js/talk.js` 用三种不同的方式回答了「不能」：没有逐字稿、字幕锚定在世界空间中，以及一个没有 WebGL 就会一片空白的页面。修复这三处问题的方法，是搭建一个小而诚实的唯一数据来源——`TALK_SCRIPT`——并在所有地方都从它读取：逐字稿列表、场景描述，以及字幕。

```js
// completed/js/main.js
function renderTranscript() {
  const list = $('transcript-list');
  list.replaceChildren(...TALK_SCRIPT.map((line) => {
    const li = document.createElement('li');
    li.textContent = line.text;
    return li;
  }));
}
```

### 第 2 步：分清「相机被移动了」和「有东西在做动画」（TODO 2、4）

`docs/en/xr-accessibility.md`（英文）明确规定了舒适度规则：*相机绝不会移动，除非学习者移动它。*不是「除非关闭了减少动态效果」——是绝不会。这也是为什么起始代码中 `app.js` 里那个被强制的相机环绕运动被直接删除，而不是包在一个 `prefers-reduced-motion` 检测里。讲解者轻微的待机晃动则不同：那是一个真正的动画，所以它遵循本课程每一节 3D 课都在用的同一条规则——在减少动态效果下默认以暂停状态开始，并且始终提供一个可见的暂停控件。

```js
// completed/js/app.js
let idleAnimating = !window.__reducedMotion;
```

### 第 3 步：把字幕锚定在观看者身上，而不是世界上（TODO 3）

一块画着字幕、静止在场景中的平面，只能从一个方向被读到。把这块平面挂载到 `camera` 而不是 `scene` 上，能让它始终停留在学习者*视野*中的同一个位置——就像视频中的字幕轨道始终停留在画面底部，无论视频里的镜头如何移动。

```js
// completed/js/talk.js
const captionPlane = new THREE.Mesh(geometry, material);
captionPlane.position.set(0, -0.32, -1); // relative to the camera, not the world
camera.add(captionPlane);
```

### 第 4 步：为每一种交互都提供一条键盘路径（TODO 5）

一个 3D 网格本身是无法用 Tab 键到达的。在这种交互原本就可以是一个普通的 HTML 控件，而不必是一个 3D 物体的地方——就像「提问」这样——这才是更简单、更稳健的修复方式，而不是一种妥协：它能用 Tab 到达，能用 Enter 或空格键激活，而且不需要任何额外的工作就满足 WCAG 2.2 的最小目标尺寸要求。

### 第 5 步：先征求同意，再感知，并说明你可能会发现什么（TODO 7、8）

WebXR 本身不允许一个页面在真实点击之外请求一个会话；请用同样的方式对待摄像头请求。`js/sensors.js` 的 `requestCamera` 只会在一个按钮自身的 `click` 处理函数内部运行，并且是在一段具体说明摄像头画面可能显示什么——而不只是「你的脸」——的提示之后。

### 第 6 步：为共享空间设置边界（TODO 9、10）

本课中的访客是模拟出来的——没有真实的多人在线服务器——但无论如何，真实的共享 XR 空间都需要同样的修复：在另一个虚拟形象靠近你之前让它停下，并提供一种在对方的存在不受欢迎时静音或屏蔽他们的方式。

```js
// completed/js/visitor.js
const PERSONAL_SPACE_RADIUS = 1.2; // metres
```

## 关键代码解析

- **`describeScene()`** 从搭建 3D 场景所依据的同一组事实，构建出 `#scene-description` 这段文字，因此两者永远不会互相矛盾。
- **挂载在 `camera` 上的 `captionPlane`** 是标准的 XR「平视显示（HUD）」技术：一个跟随观看者头部移动、而不是固定在世界中的物体，和 4.2 中世界内菜单用的是同一个思路，只不过这次用在了文字上，而不是按钮上。
- **`requestCamera(onGranted, onDenied)`** 自身绝不会主动运行；它的存在只是为了被一个点击处理函数调用，因此摄像头请求始终跟在一次真实的、经过充分告知的用户手势之后。
- **`PERSONAL_SPACE_RADIUS`** 是一次简单的距离检测，在 `visitor.update()` 中每一帧都对访客和相机之间的距离运行一次——整个「边界」就是这一个比较。
- **`window.__reducedMotion`**，在模块脚本运行之前，从 `matchMedia('(prefers-reduced-motion: reduce)')` 读取一次，决定讲解者的待机动画是以开启还是关闭状态启动。

## 3D 与 XR 无障碍

本课自始至终都是 3D 和 XR 的，因此它的无障碍要求就是 [`docs/en/xr-accessibility.md`](../../docs/en/xr-accessibility.md)（英文）中的人工检查项，具体应用到这个展览讲解场景中：

| 检查项 | 这个场景如何满足它 |
| --- | --- |
| 场景描述 | `#scene-description`，由 `describeScene()` 构建。 |
| 每种交互都有键盘路径 | 「开始讲解」「关闭字幕」「暂停讲解者动画」「提问」、摄像头同意按钮，以及「静音」/「屏蔽访客」，全部都是普通的 `<button>` 元素。 |
| 减少动态效果 | 在 `prefers-reduced-motion` 下，讲解者的待机动画会以暂停状态开始；无论如何，相机都绝不会自行移动。 |
| 2D 后备方案 | 逐字稿、答案文字、同意面板和访客控件，在禁用 WebGL 的情况下都能正常工作。 |
| 舒适度 | 没有被强制的相机路径。访客会在个人空间距离处停下，而不是无限制地靠近。 |

## 无障碍要求

| 要求 | WCAG 2.2 | 原因 |
| --- | --- | --- |
| 每一句语音都有对应的文字，并且在播放开始之前就已经存在 | 1.1.1 | 一位听不到语音合成的学习者，或浏览器不支持它的学习者，依然能获得内容。 |
| 无论学习者看向哪里，字幕都保持在可见范围内 | 良好实践（没有单独一条成功标准覆盖 3D 中的实时字幕） | XAUR 用户需求 19 直接提到了这一点；WCAG 的字幕相关标准是针对预先录制的视频写的。 |
| 没有自动的相机运动 | 2.2.2 | 被强制的视角移动是导致 VR 晕动症的主要原因（XAUR 用户需求 16）。 |
| 每一个可交互控件都能用键盘到达 | 2.1.1 | 不是每一位学习者都能精确地用鼠标或 VR 控制器指向目标。 |
| 可交互控件满足最小目标尺寸 | 2.5.8 | 支持行动不便或视力受限的学习者（XAUR 用户需求 4）。 |
| 只有在给出清楚的说明并获得一次真实点击之后，才会请求一个传感器（摄像头、麦克风） | 良好实践（不在 XAUR 和 WCAG 的范围之内） | 同意必须先于访问，而不是事后补上。 |

## 性能注意事项

- 这个场景只有三个小型网格、一位讲解者和一位访客：即使在配置一般的笔记本电脑和中端手机上，也能流畅渲染。
- `SpeechSynthesisUtterance` 在设备本地运行；它不会增加任何网络请求，也没有可测量的负载。
- 访客的位置更新运行在一个普通的 `setInterval` 中，而不是在渲染循环内部，因此暂停标签页（`visibilitychange`）不会同时冻结个人空间检测，导致标签页重新可见时出现「瞬移」——`visitor.update()` 中的距离限制每次都会基于当前的位置重新检测。

## 常见错误

| 错误 | 会发生什么 | 应该怎么做 |
| --- | --- | --- |
| 用 `prefers-reduced-motion` 包裹被强制的相机环绕运动，而不是直接删除它 | 没有开启减少动态效果的学习者，依然会遇到无法控制的相机运动 | 彻底删除被强制的相机运动；只有学习者自己的输入才应该移动相机。 |
| 为了同意或多人安全，引用一个 XAUR「用户需求」编号 | 这歪曲了一份 W3C 工作组说明实际说了什么 | 像 `completed/audit.md` 那样，明确说明 XAUR 没有涵盖这一点。 |
| 把字幕挂载到相机上，却忘记了 DOM 字幕条 | 头显用户能看到字幕；在页面上使用辅助技术的桌面端学习者却看不到，因为 3D HUD 对他们不可见 | 两者都保留：一个挂载在相机上的平面用于演示，一个 DOM 元素用于普通页面视图。 |
| 一滚动到「个性化」这一节就请求摄像头 | 依然不是一次真正由点击触发的请求 | 只在按钮自身的 `click` 处理函数内部请求。 |

## 故障排查

**语音始终不播放。** 有些浏览器只有在页面被交互过一次之后，才会暴露 `speechSynthesis` 的语音列表，或者需要一点时间异步加载语音。无论如何，逐字稿依然能正常工作；这正是逐字稿存在的意义所在——用来弥补这种缺口。

**「Enter VR」始终不出现。** 这说明该浏览器或设备不支持 `immersive-vr`。讲解、逐字稿和每一个控件在没有它的情况下都完全可用。

**摄像头个性化始终失败，即使已经授权。** 在 Firefox 中，检查地址栏挂锁图标的「权限」面板；在 Safari 中，检查「Safari → 设置 → 网站 → 摄像头」。两者都必须对这个页面的来源显示「允许」。

**静音之后，访客的聊天声始终不停止。** 确认你按下的是「静音访客」本身，而不是「屏蔽访客」——静音会停止聊天，但访客依然可见并继续靠近；屏蔽会同时停止这两者。

## 值得认识的女性

Wanda Díaz-Merced 是一位波多黎各天文学家，在年轻求学时期失去了视力，后来成为现代天文学中「数据声音化（sonification）」的先驱——把天体物理数据转化为声音，从而可以用耳朵而不是眼睛来研究。她拥有格拉斯哥大学的博士学位，曾在哈佛-史密森天体物理中心、南非天文台和欧洲引力天文台担任研究职位。

她的工作正是对本课主题的一个直接回应：数据声音化没有把一位盲人科学家的需求当作事后才想起的补充，而是让整个数据集能够通过一种与最初设计意图不同的感官被感知——这正是本课为讲解提供完整文字逐字稿和完整 2D 后备方案背后的同一个原则，而不只是在一个以视觉为先的设计上，象征性地加上一点无障碍点缀。她持续为 STEM 领域中的残障包容发声。

## 标准聚焦

W3C 发布多种不同类型的文档，本课刻意各用了一种。WCAG 2.2 是一份**推荐标准（Recommendation）**：W3C 最成熟的状态，通过一套正式流程达成，也是本课程每一节课都用来检验自身的标准。XAUR 是一份**工作组说明（Group Note）**：一个工作组研究成果和社区意见的快照，为了分享知识而发布，但从未经过推荐标准流程，也从未作为标准被表决通过。一份工作组说明是有价值的——就撰写本文时而言，XAUR 是关于残障用户在 XR 中需要什么的、最详尽的公开资料——但如果引用它时，把它当作和 WCAG 具有同等权威、能够一锤定音的标准，就夸大了它本身的性质。好的做法是清楚说明你引用的到底是什么：一份推荐标准、一份说明，或者，在两者都没有涉及的地方，你自己经过推理的判断。
