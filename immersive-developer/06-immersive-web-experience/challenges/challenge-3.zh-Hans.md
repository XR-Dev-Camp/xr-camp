# 挑战 3：探索

**进阶选做。** 约 90 分钟。

在一台支持它的手机或头显上，用一个真正的 `immersive-ar` hit-test 会话，替换 2D 的「放置标记」占位方案。

## 任务

1. 阅读 WebXR Device API 的 hit-test 说明文档（链接见 README 的延伸阅读）。
2. 在一个新的 `js/ar.js` 中，用 `requiredFeatures: ['hit-test']` 请求一个 `immersive-ar` 会话，遵循和 `js/xr.js` 对 VR 已经遵循的同一条「只从一次真实点击中请求」规则。
3. 从观看者参考空间创建一个 `XRHitTestSource`，并在每一帧用它的结果，让一个瞄准环网格在摄像头看到的任何真实表面上移动。
4. 在屏幕点按（或一次 XR `select` 事件）时，把 `js/interact.js` 已经创建的同一个标记，放置在瞄准环报告的位置上，而不是一个固定的位置。
5. 保留现有的「放置标记」按钮，作为没有 AR 硬件的人的 2D/键盘对等方式——不要删除它。
6. 如果你有条件的话，在一台真实支持 AR 的设备上测试；如果没有，就像本结业项目自己的 `1.0.0` 条目对待它未经测试的硬件路径那样，在 `CHANGELOG.md` 中诚实地说明这一点。

## 为什么这很重要

Hit-test AR 是本结业项目参考答案中，唯一用 2D 占位方案替换掉的 4.2 内容，因为它需要大多数学习者都没有的硬件。搭建真正的版本，并诚实说明你测试过什么、没测试过什么，正是 4.6 测试矩阵这个习惯存在的意义。

## 完成标准

- [ ] `js/ar.js` 在支持的硬件上请求一个带有 hit-test 的真实 `immersive-ar` 会话。
- [ ] 现有的「放置标记」按钮依然能作为 2D/键盘对等方式正常工作。
- [ ] `CHANGELOG.md` 清楚说明了在真实硬件上测试过什么、没测试过什么。
