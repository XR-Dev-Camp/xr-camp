# 挑战 3：探索

**进阶选做。** 约 90 分钟。

添加第四种锁定模式：手部相对（hand-relative，有时也叫「掌心 UI」），这种模式只有在真正的手部或控制器追踪可用时才有意义——把它和你在 **4.2：XR 输入与交互**中已经学到的知识联系起来。

## 任务

1. 回顾一下你在 4.2 中关于 `XRControllerModelFactory` 以及控制器/手部姿态的笔记。这个挑战不要求你重新搭建那节课的交互实验室——只需要复用「把一个物体相对于一只被追踪的手或控制器来放置」这个想法。
2. 在 `js/layout.js` 中，添加第四个函数 `applyHandLock(object, handOrControllerSpace, localOffset)`，让它像 `applyBodyLock` 相对于相机定位物体那样，把 `object` 相对于一个被追踪的 `XRSpace` 来定位。如果你没有支持手部追踪的头显可以测试，可以用 4.1 中的 Immersive Web Emulator 来模拟这个被追踪的空间，或者暂时用任意其他 Object3D（用一个立方体代替一只手）来证明定位的数学计算是正确的。
3. 为目标面板的锁定模式控件添加第四个选项，并通过 `setLockMode` 把它接通。
4. 更新 `js/describe.js` 和你的 `design-rationale.md`，解释一个手部相对面板在什么情况下有意义、什么情况下没有意义（想一想，当头显的摄像头看不到手的时候，会发生什么）。

## 为什么这很重要

真实的空间界面会根据头显实际能追踪到什么，混合使用多种锚定策略，而手部追踪是最不可靠的输入方式之一（参见 4.2 自己关于支持情况参差不齐的提醒）。为一种可能悄无声息消失的模式做设计，比本课保证可用的那三种模式，是一个更难、也更贴近现实的问题。

## 完成标准

- [ ] `applyHandLock` 已经存在，并且通过某个可以演示的东西（哪怕只是一个替代物体）得到了验证。
- [ ] 目标面板可以从页面的控件中切换到这个新模式。
- [ ] `design-rationale.md` 解释了手部相对 UI 的一个真实局限性，而不只是你是怎么搭建它的。
