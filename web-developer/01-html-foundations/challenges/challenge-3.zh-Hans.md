# 挑战 3：探索

**可选，进阶。** 约两小时。

添加机器可读的结构化数据，以及一份无障碍声明。

## 任务

### A 部分 — 结构化数据

如果你用专为机器设计的格式描述页面，搜索引擎和辅助工具就能更好地理解它。在 `<head>` 中添加一个 `<script type="application/ld+json">` 区块，使用 [schema.org](https://schema.org/) 词汇表——社区页面适合用 `Organization` 或 `LocalBusiness`。

包含名称、地址、电话和营业时间。使用 [Schema Markup Validator](https://validator.schema.org/) 进行测试。

请注意你在这里做的事：同样的事实被陈述了两次，一次给人看，一次给机器看。想一想，当两者不再一致时会发生什么。

### B 部分 — 无障碍声明

新增 `accessibility.html`，如实说明：

- 你为使页面无障碍做了哪些工作。
- 你如何测试，使用了什么工具。
- 你已知仍然存在的问题。
- 别人如何向你反馈问题。

## 为什么这很重要

A 部分是网页得以被机器读懂的方式，也是第 4、5 阶段空间数据与语义数据工作的直接前身。

B 部分更为重要。许多公共机构在法律上必须发布无障碍声明，而其中大多数并不诚实——声称完全合规，实则不然。写一份诚实的声明，包括你没能做到的部分，是现在就值得养成的职业习惯。没有人能发布一个完美无障碍的网站。坦率承认这一点，正是专业人士与推销者的区别。

## 完成标准

- [ ] 结构化数据通过 Schema Markup Validator 且零错误。
- [ ] 结构化数据中的事实与可见页面完全一致。
- [ ] `accessibility.html` 已创建，从页脚链接可达，并写明至少一项真实存在的不足。
- [ ] 你使用真实的屏幕阅读器进行了测试，并描述了测试发现。
