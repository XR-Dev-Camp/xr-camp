# HTML 基础

**Language / Idioma / 语言:** [English](README.md) · [Español](README.es.md) · [简体中文](README.zh-Hans.md)

**课程：** `web-developer` · **课时：** `html-foundations-01` · **时长：** 约 12 小时 · 16 次学习，每次 45 分钟 · 每周 4 次，约 4 周

> 构建一个无障碍的个人或社区信息网站。

## 学习目标

完成本项目后，你将能够：

1. 凭记忆写出一个有效的 HTML 文档，并解释 `<head>` 中每个部分的作用。
2. 依据文档结构而非文字大小来选择标题层级。
3. 使用语义化地标元素（`<header>`、`<nav>`、`<main>`、`<footer>`），让辅助技术能够浏览你的页面。
4. 撰写传达图片**用途**而非描述其外观的替代文本。
5. 为真正的表格数据添加表头与作用域，使屏幕阅读器能够正确解读。
6. 嵌入带字幕的视频或音频，并为无法播放的浏览器提供后备内容。
7. 撰写脱离上下文也能读懂的链接文字。
8. 校验你的 HTML，并读懂校验器的输出。

### 第 1 步 —— 描述页面（TODO 1–2）

添加 `<meta name="description">`，并写一个真正的 `<title>`。

刷新页面。浏览器顶部的标签页现在显示你的标题。它是屏幕阅读器最先朗读的内容，也是搜索引擎展示的文字。它值得比大多数人所给予的更多思考。

### 第 2 步 —— 跳转链接（TODO 3）

```html
<a href="#main">跳转到主要内容</a>
```

把它紧接着放在 `<body>` 之后。刷新页面并按一次 **Tab**，该链接会获得焦点。

它之所以存在，是因为否则键盘用户必须在每个页面上逐个跳过所有导航链接才能到达正文。你正在从第一个元素起就把无障碍内建进去，而不是事后再补——这正是整个课程希望你养成的习惯。

### 第 3 步 —— 页眉与标题（TODO 4）

一个 `<h1>`，写明网站名称。随后是一小段介绍文字。

每页有且只有一个 `<h1>`。它回答的是「这个页面是什么」，而不是「哪段文字最大」。

### 第 4 步 —— 把导航写成列表（TODO 5）

```html
<nav aria-label="主导航">
  <ul>
    <li><a href="#about">关于我们</a></li>
  </ul>
</nav>
```

为了一个最终只显示成普通项目符号列表的东西多打这些字，似乎不值得。但屏幕阅读器会朗读*「列表，共 4 项」*，用户在进入导航之前就知道前面有多少内容。零散的 `<a>` 元素给不了他们这些信息。

### 第 5 步 —— 板块与标题（TODO 6）

四个 `<section>` 元素，每个都带有与导航链接对应的 `id`，以及一个 `<h2>`。

现在测试你的导航：点击一个链接，浏览器会跳到该板块。你完全没有使用 JavaScript，就实现了可用的页内导航。

### 第 6 步 —— 文字与图片（TODO 7）

先写段落，再添加图片。

替代文本是本项目中最难的部分。试试这个方法：用手遮住图片，把你的替代文本朗读出来。有信息丢失吗？那就是写得太短。是不是在罗列没人需要的细节？那就是太长。

```html
<img src="../assets/centre-exterior.jpg"
     alt="活动中心正门，大门旁设有无台阶坡道。"
     width="800" height="450">
```

这段替代文本提到坡道，是因为*无障碍信息对这个受众群体很重要*。换一个页面，对同一张照片给出不同的描述也完全合理。语境决定一切。

### 第 7 步 —— 表格（TODO 8）

```html
<table>
  <caption>学期内营业时间</caption>
  <thead>
    <tr><th scope="col">星期</th><th scope="col">开门</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">星期五</th><td>9:00</td></tr>
  </tbody>
</table>
```

真正起作用的是 `scope` 属性。它让屏幕阅读器朗读出*「星期五，开门，9:00」*，而不是孤零零的「9:00」。没有它，对看不到表格形状的人来说，这张表只是一堆毫无意义的数字。

### 第 8 步 —— 列表与媒体（TODO 9）

顺序无关时用 `<ul>`，顺序有意义时用 `<ol>`。然后添加带 `controls` 的视频或音频、一个 `<track kind="captions">`，以及标签之间的后备内容。

你需要媒体文件。参见 [`assets/README.md`](assets/README.md)：可以用手机录十秒，也可以采用其中说明的占位方案。

### 第 9 步 —— 联系方式（TODO 10）

`<dl>` 把每个标签与其内容配对。使用 `tel:` 和 `mailto:` 链接，手机用户轻点即可拨号。

### 第 10 步 —— 页脚（TODO 11）

一个「返回顶部」链接、用 `<small>` 标注的小字说明，以及一个 `<time datetime="2026-07-30">` 元素。

### 第 11 步 —— 校验

把你的 HTML 粘贴到 [W3C 校验器](https://validator.w3.org/#validate_by_input)。修正每一个错误。警告值得阅读，但并不总是需要处理。

请阅读提示信息本身，而不是靠模式匹配。「End tag `li` implied」是在具体告诉你，浏览器认为你的列表在哪里结束了。

## 关键代码解析

### 为什么你的页面没有 CSS

用浏览器打开 [`completed/index.html`](completed/index.html)。它很朴素：黑色文字、蓝色链接、默认字体。但它*完全可用*：可以阅读、可以用键盘浏览，屏幕阅读器也能正确朗读每个部分。

这是本项目最重要的一个观念。结构良好的 HTML 文档本身就已经是无障碍的、自适应的、可用的。CSS 装点的是一个本来就能用的页面；它无法拯救一个不能用的页面。

大多数初学者把这件事学反了——他们立刻去写样式，做出看起来很漂亮、却让相当大一部分潜在受众无法使用的东西，而且自己从来不会知道。你正在以正确的顺序学习它。

### 地标元素与屏幕阅读器的浏览方式

`<header>`、`<nav>`、`<main>` 和 `<footer>` 是*地标元素*。屏幕阅读器用户会在它们之间直接跳转，就像你快速浏览时视线会跳到标题一样。

完全由 `<div>` 构成的页面没有任何地标。它渲染出来一模一样，却难用得多。这就是为什么「语义化 HTML」不是一种风格偏好——语义本身就是无障碍。

### 标题是提纲，不是字号

标题层级构成文档的目录。屏幕阅读器用户经常靠标题来浏览，而从 `<h2>` 直接跳到 `<h4>`，读起来就像缺了一节——如同一本书从第 2 章直接跳到 2.1.3 小节。

如果某个标题显得太大，那是 CSS 的问题，应当用 CSS 解决。绝不要靠改变层级来解决。

## 无障碍要求

你的作业必须满足以下全部要求。这些会在 [`tests/checklist.md`](tests/checklist.md) 中逐项检查。

| 要求 | WCAG 2.2 | 原因 |
| --- | --- | --- |
| `<html lang="zh-Hans">`（或你所用的语言） | 3.1.1 | 告诉屏幕阅读器使用哪套发音规则。缺少它，中文被英语语音朗读将无法理解。 |
| 只有一个 `<h1>`；不跳级 | 1.3.1 | 许多人正是靠标题导航来阅读。 |
| 每个 `<img>` 都有 `alt` | 1.1.1 | 装饰性图片使用 `alt=""`：内容为空，但属性必须存在。 |
| 跳转链接位于 `<body>` 最前 | 2.4.1 | 用于跳过重复的导航。 |
| 链接文字单独可读 | 2.4.4 | 用户可以调出剥离上下文的链接列表。 |
| 表格使用 `<caption>` 与 `scope` | 1.3.1 | 把每个单元格与其表头关联起来。 |
| 媒体带字幕 | 1.2.2 | 服务于聋人和听力障碍者，以及身处嘈杂或需静音环境的人。 |
| 一切都可用键盘到达 | 2.1.1 | 很多用户从不使用鼠标。 |

**请亲自测试。** 把鼠标放到一边，只用 **Tab**、**Shift+Tab** 和 **Enter** 浏览整个页面。如果你到不了某个地方，大量用户同样到不了。然后试用屏幕阅读器——NVDA（Windows，免费）、VoiceOver（macOS 与 iOS，系统自带）或 TalkBack（Android，系统自带）。花十分钟听一听自己的页面，胜过读任何文章。

## 性能注意事项

这里没有 JavaScript 也没有 CSS，所以你的页面本来就很快。有两个习惯值得现在就养成：

1. **给图片设置 `width` 和 `height`。** 浏览器会在图片到达之前预留空间，文字就不会在加载过程中跳动。这种跳动称为布局偏移，是人们对当今网站最常见的抱怨之一。
2. **上传前先压缩图片。** 手机直出的照片可能有 4 MB。以 800px 宽度显示时，大约 150 KB 就够了。对使用按流量计费的移动网络的读者来说，这个差别就是实实在在的钱。

## 常见错误

| 错误做法 | 为什么不对 | 正确做法 |
| --- | --- | --- |
| 按字号大小选择标题层级 | 破坏文档提纲 | 按结构选择；日后用 CSS 调整大小 |
| `alt="图片"` 或 `alt="照片"` | 没有传达任何有用信息 | 描述用途；装饰性图片用 `alt=""` |
| 用「点击这里」作为链接文字 | 在链接列表中毫无意义 | 写明链接的目标 |
| 用表格做页面布局 | 对屏幕阅读器毫无意义 | 表格只用于数据 |
| 省略 `<caption>` 与 `scope` | 单元格失去表头关联 | 两者都必须写 |
| 使用多个 `<h1>` | 页面主旨含混不清 | 有且只有一个 |
| 忘记写 `lang` | 屏幕阅读器发音错误 | 在 `<html>` 上设置 |
| 忽略校验器报错 | 小错误会不断累积 | 提交前修正全部错误 |

## 故障排查

**页面一片空白。** 检查文件是否名为 `index.html`，以及是否通过「文件 → 打开文件」打开。空白通常意味着靠近顶部有未闭合的标签——去做校验。

**图片不显示。** `src` 路径是相对于该 HTML 文件的。检查拼写和大小写：在大多数网页服务器上 `Photo.JPG` 和 `photo.jpg` 是两个不同的文件，尽管 Windows 视其为同一个。

**页内链接没有反应。** `href="#about"` 必须与某个 `id="about"` 完全一致。区分大小写，且 `id` 本身不带 `#`。

**视频无法播放。** 各浏览器支持的格式不同，MP4（H.264）最为稳妥。如果显示的是后备文字，说明文件缺失或路径有误。

**校验器报了我看不懂的错误。** 先修正第一个错误再重新校验。一个未闭合的标签常常会引发十个错误，而它们往往会一起消失。

## 3D 时刻

在**欢迎来到 XR Camp**中，你在第一个小时里就构建了一个 3D 世界。现在把它放进你的页面。

1. 把那个世界的 `index.html` 复制到名为 `world/` 的文件夹中，与本项目的 `index.html` 放在同一目录。
2. 把它添加到你的某个分区中：

```html
<figure>
  <iframe src="world/index.html"
          title="我的第一个 3D 世界：有三个形状的花园"
          width="800" height="450" loading="lazy"></iframe>
  <figcaption>我的第一个 3D 世界。拖动或使用方向键环顾四周。</figcaption>
</figure>
```

`<iframe>` 上的 `title` 就是屏幕阅读器会朗读的内容，和图片的替代文本一样。`<figcaption>` 告诉每个人如何使用它。设置 `width` 和 `height` 的原因与图片相同：世界加载时页面不会跳动。

本项目完全建立在两项开放标准之上：[HTML Living Standard](https://html.spec.whatwg.org/multipage/)（WHATWG）与 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)（W3C）。两者都是公开的、可免费阅读的，并且接受任何人提出意见——包括你。你今天所写的一切，不依赖任何一家公司的产品。
