# 第一阶段结业项目 - Web 开发者作品集

**Language / Idioma / 语言:** [English](README.md) · [Español](README.es.md) · [简体中文](README.zh-Hans.md)

**课程:** `web-developer` · **课时:** `web-developer-portfolio-09` · **时长:** 约 15 小时 · 20 次学习，每次 45 分钟 · 每周 4 次，约 5 周

---

> 发布一个专业、无障碍、响应式的作品集，其中包含多个已完成的网页项目。

---

## 学习目标

完成本项目后，你将能够：

1. 围绕一类读者和一个目标来规划网站，并在动手构建之前画出它的结构。
2. 挑选你最好的项目，并用平实的语言描述每一个：它是什么、为谁而做、你做了什么。
3. 写一篇案例研究，展示你的过程和决策，而不只是最终结果。
4. 重复使用课程 1.1 到 1.4 中的语义化 HTML、基于设计变量（tokens）的 CSS 和响应式布局，快速构建一个新网站。
5. 给网站赋予你自己的视觉风格，并检查每一种颜色的对比度。
6. 用课程 1.5 中的方法对你自己的网站做无障碍审查，并修复你发现的问题。
7. 添加能改善页面、但使用页面时并不依赖它的 JavaScript。
8. 在真实设备上测试，让页面保持快速，并在 README 中记录你的工作。
9. 用 GitHub Pages 发布你的作品集，并决定哪些个人信息永远不要发布。

## 先决条件

- **课程 1.1–1.6。** 你已经构建了一个无障碍、带样式、响应式的网站，审查过一个页面，也写过 JavaScript。
- **课程 1.7 和 1.8。** 你会用开发者工具找问题，也会用 Git 和 GitHub Pages 发布网站。
- 第一阶段中**至少三个已完成的项目**。它们不需要完美。

## 你将构建什么

你的**作品集**：一个小巧、快速的网站，展示你是谁，以及你能构建什么。它包括：

- 一个**首页**，用两句话说明你是谁、你构建什么；
- 一个**项目板块**，第一阶段的每个项目都有一张卡片：一张图片、它是什么、为谁而做、它展示了哪些技能，以及指向在线项目和代码的链接；
- 至少一篇完整的**案例研究**：问题、读者、你的过程、你的决策及其原因、你的无障碍工作，以及你学到了什么；
- **联系方式**，让别人能联系到你，又不泄露你的隐私；
- 一个展示你的项目的小型 **3D 展厅**，并用一份同样项目的普通列表作为后备方案。

这是第一阶段的结业项目：课程 1.1 到 1.8 中的每一项技能都会用到。它也是未来的雇主、客户或老师看到你作品时的第一印象，所以在 XR Camp 接下来的学习中，你会一直保留并更新它。

[`completed/`](completed/) 中的参考解决方案是 Ana 的作品集，其中有一篇案例研究，讲的是她在课程 1.1 到 1.6 中构建的 Riverside Community Centre（河畔社区中心）网站。你的作品集将讲你自己的项目，用你自己的话。

### 第 1 步：规划你的作品集

在写任何代码之前，先在学习日志中回答三个问题：

1. **它是给谁看的？** 选一位主要读者：招聘初级开发者的雇主、需要网站的小机构、一所大学，或者一个奖学金项目。你没法同时为所有人写好。
2. **他们应该在 30 秒内了解到什么？** 大多数人只是快速浏览。写下你希望他们记住的那一句话。
3. **他们接下来应该做什么？** 通常是：读一篇案例研究，然后联系你。

Ana 的计划是：*「给小机构，以及正在招聘初级开发者的团队看。他们应该在 30 秒内了解到，我构建的是人人都能使用的网站。然后他们应该读我的 Riverside 案例研究，并给我发邮件。」*

### 第 2 步：挑选项目并收集证据

三到五个好项目，胜过十个小项目。对每一个可能放进去的项目，写下：

| 问题 | 以 Riverside 为例 |
| --- | --- |
| 用一句话说，它是什么？ | 一个社区中心的网站，在任何屏幕上都能用 |
| 它是为谁做的？ | 当地的家庭，其中很多人用手机 |
| **你**做了什么？ | 全部：内容、HTML、CSS、测试 |
| 它在哪里？ | `projects/riverside/index.html` |
| 哪张图片最能展示它？ | 首页在手机上的截图 |
| 你为什么感到自豪？ | 开放时间表格在屏幕阅读器中也能正常使用 |

然后收集你的**证据**：你的笔记、课程 1.4 中的测试记录、课程 1.5 中的审查、修改前后的截图。案例研究就是用这些材料写成的。

对每个项目是什么，要诚实。练习项目，或者像 Riverside 这样虚构的机构，都没有问题：说明就好。一步一步照抄的教程不是你的项目；但如果你修改并扩展了一个教程，只要说明你加了什么，它就可以算。

### 第 3 步：信息架构

**信息架构**的意思是，在动手构建之前，先决定什么东西放在哪里、叫什么名字。在纸上画出你的网站地图：

```text
Home (index.html)
├── About me          (#about)
├── Projects          (#projects)  →  one card per project
│   └── Case study    (case-study.html)
├── How I built this site (#this-site)
├── Contact           (#contact)
└── 3D gallery        (gallery-3d.html)
```

也就是：首页；下面有「关于我」「项目」（每个项目一张卡片，其中链接到案例研究页面）「我是怎样构建这个网站的」「联系方式」，以及单独的 3D 展厅页面。

一个小型作品集可以是一个分成几个板块的页面，再加上每篇案例研究各一个页面。导航链接要用平实的词来命名：用「Projects」（项目），而不是「Work showcase」（作品展示）；用「Contact」（联系），而不是「Let's connect」（我们联系吧）。每个页面都使用**同样顺序的同一套导航**，这样人们永远不用学第二遍。

### 第 4 步：写出你的文字（TODO 1–2）

在设计任何样式之前，先写出你的文字。再漂亮的页面也救不了不清楚的文字，而清楚的文字即使是纯 HTML 也很好看。

- **TODO 1：** 在标题、描述和页眉中写上你的名字。
- **TODO 2：** 你的自我介绍和「About」（关于我）板块。

平实语言的小建议：

- 从你是谁、你构建什么开始：*「我构建人人都能使用的网站。」*
- 句子要短。一句一个意思。
- 写别人能**核实**的事情，而不是形容词。*「我用屏幕阅读器测试」*比*「对无障碍充满热情」*更有说服力。
- 还在学习并不是弱点。*「我正在 XR Camp 学习网页开发」*是真实的，也让别人知道该期待什么。
- 大声读出来。如果读得磕磕绊绊，就重写。

### 第 5 步：项目卡片（TODO 3）

每个项目都是列表中的一张卡片，就像课程 1.4 中的项目卡片一样：

```html
<li class="card project" data-skills="responsive accessibility">
  <img src="centre.svg" alt="" width="800" height="450">
  <h3>Riverside Community Centre website</h3>
  <p>A website for a community centre: opening hours, programmes, and how to visit, on any screen.</p>
  <p><strong>Built for:</strong> local families, many on phones.</p>
  <ul class="tags" aria-label="Skills">
    <li>HTML</li>
    <li>CSS grid</li>
  </ul>
  <p class="links">
    <a href="case-study.html">Read the Riverside case study</a><br>
    <a href="projects/riverside/index.html">Visit the Riverside website</a>
  </p>
</li>
```

这张卡片里有三个决策：

- **图片上的 `alt=""`。** 标题已经说出了项目的名字，所以图片对屏幕阅读器用户来说没有增加任何信息。如果你的图片展示了文字没有说到的内容，就改为描述那部分内容。
- **说明链接去哪里的链接文字。** 四张卡片上都写着「Demo」（演示）和「Code」（代码），屏幕阅读器用户得到的就是一串听起来都一样的链接。「Visit the Riverside website」（访问 Riverside 网站）放在哪里都很清楚。
- **每张图片都有 `width` 和 `height`。** 浏览器会在图片到达之前留好合适的空间，这样页面在加载时就不会跳动。

图片可以用项目的截图，或者一张简单的绘图。截图保存为大约 1000 像素宽：一张原尺寸的截图，可能比你整个网站还要重好几倍。永远不要在未经允许的情况下使用别人的照片，也永远不要使用显示了真实人物姓名或数据的截图。

### 第 6 步：联系方式和隐私（TODO 4）

你的作品集是公开的：世界上任何人都能读到它、复制它，而且是永久的。在写联系方式板块之前，先决定哪些东西**不**发布：

| 不要发布 | 原因 | 替代做法 |
| --- | --- | --- |
| 你的家庭住址 | 任何人都能找到你的家 | 你所在的城市或国家，如果你愿意的话 |
| 你的私人电话号码 | 垃圾信息、诈骗和骚扰电话 | 一个电子邮箱地址 |
| 你的身份证号、出生日期或护照 | 身份盗用 | 不写：没有人需要从作品集里得到这些 |
| 你孩子或家人的照片 | 他们的隐私不该由你交出去 | 不放 |
| 带有真实人物数据的截图 | 他们的隐私，也可能涉及法律 | 使用编造数据的截图 |
| 代码中的密码、API 密钥或令牌 | 任何人都能使用它们 | 不要把它们放进任何公开仓库 |

**专门为作品集注册一个新的电子邮箱地址。** 如果它收到垃圾邮件，你可以关掉它，而不会失去你的私人邮箱。用 `mailto:` 链接到它：

```html
<a href="mailto:ana.builds@example.com">ana.builds@example.com</a>
```

把邮箱地址也作为链接文字显示出来，这样如果对方的设备上没有邮件应用，也能复制它。

### 第 7 步：你的视觉风格（TODO 10）

你的样式表就是课程 1.3 和 1.4 中的 Riverside 样式表。布局、间距和响应式规则都已经能正常工作。要让它变成你的，只修改顶部的**设计变量**（design tokens）：改的是值，永远不要改名字。

Ana 选择了深蓝绿色、赤陶色和暖沙色。选择让你觉得像自己的颜色：来自你的文化、你的城市，或者一个你喜爱的地方。然后在[对比度检查器](https://webaim.org/resources/contrastchecker/)（英文）中检查每一种文字颜色：

- 背景、表面和色带上的文字：**至少 4.5:1**。
- 焦点轮廓和表单边框：**至少 3:1**。

像 Ana 那样，把对比度写在颜色上方的注释里。如果某个颜色没有通过，就把它调暗一点，再检查一次；大多数颜色都有一个感觉依然相同、但更深的版本。

保留系统字体。它们不需要下载，而且字体列表中已经包含了适用于中文和带重音字母的字体。

### 第 8 步：响应式布局（TODO 11）

你的卡片已经是一个响应式网格了。在 TODO 11 中，你要为宽屏添加一种布局：把案例研究的关键信息排成两栏。

```css
@media (min-width: 48rem) {
  .facts {
    grid-template-columns: max-content 1fr;
    column-gap: var(--space-4);
  }
}
```

`max-content` 让第一栏的宽度恰好等于最长的那个术语，例如「My role」（我的角色）；`1fr` 把剩下的空间留给答案。然后像课程 1.4 中那样，在设备模式下用 **320、390、768 和 1280 像素**的宽度测试每一个页面。

### 第 9 步：案例研究（TODO 5–9）

截图展示的是你做了**什么**。案例研究展示的是**你怎样思考**，而这正是招聘的人和教学的人想看的。选择你从中学到最多的项目，而不是看起来最好看的那一个。

| 部分 | 回答什么 | TODO |
| --- | --- | --- |
| 关键信息 | 你的角色、时间、工具、链接，如果是练习项目，还要诚实地注明 | 5 |
| 问题 | 人们需要什么，是什么阻碍了他们 | 6 |
| 为谁而做 | 这些人，以及每类人身上改变了你构建方式的一点 | 6 |
| 我的过程 | 按顺序列出的各个阶段 | 7 |
| 决策 | 你选择了什么、为什么，以及你还考虑过什么 | 7 |
| 无障碍 | 你做了什么、怎样测试的，以及哪些地方还不完美 | 8 |
| 成果和收获 | 你能衡量的东西、你学到了什么，以及下一步你会做什么 | 9 |

**决策**是核心。每一个都分三部分来写：

> **我选择了：** 把一个真正的表格放进一个可以横向滚动的框里。
> **原因：** 真正的表格能让屏幕阅读器用户在听到每个时间时都听到对应的是哪一天。
> **我还考虑过：** 用 CSS 把表格变成一个个区块。

一个一开始做错了的决策，以及你后来怎样改正，往往是最有意思的内容。Ana 的第四个决策，就是她用屏幕阅读器发现的一个错误。

**写一写你的无障碍工作。** 大部分无障碍工作是看不见的：没有人能看到一个良好的标题顺序或一个标签。如果你不说，就没有人知道你做过。也要说出哪些地方还不完美：诚实比声称一切完美更有说服力。

### 第 10 步：改善页面的 JavaScript

打开 `portfolio.js`。它已经写好了：读一读它，逐行给自己讲清楚。它就是课程 1.6 中的项目浏览器的缩小版：找到元素，监听变化，判断哪些卡片匹配，然后朗读结果。

重要的思路是**渐进增强**。筛选器在 HTML 中一开始是 `hidden`（隐藏）的：

```html
<fieldset id="filters" class="filters" hidden>
```

只有脚本才会把它显示出来：

```js
filters.hidden = false;
```

所以，如果脚本没能加载（因为网络慢，或者出了错误），访客会看到所有项目，而不会看到坏掉的控件。页面首先要能用，JavaScript 让它变得更好。

测试一下：先用鼠标选择每一个筛选条件，再用键盘（按 **Tab** 到这一组，然后用**方向键**），再打开屏幕阅读器，听它是否朗读「Showing 1 of 4 projects」（显示 4 个项目中的 1 个）。

### 第 11 步：审查你的作品集

用课程 1.5 中的方法，在每一个页面上审查你自己的作品集：

1. **键盘：** 用 Tab 键走遍所有内容。焦点是否一直可见？你能到达并使用每一个链接和控件吗？
2. **屏幕阅读器：** 列出所有标题和链接。它们单独出现时能说得通吗？筛选器会朗读数量吗？
3. **缩放、颜色和动态效果：** 200% 和 400% 缩放；每种颜色都已检查；没有东西会自己移动。
4. **自动化工具：** 在每个页面上运行 axe DevTools 或 WAVE。然后记住它有哪些检查不了。

像课程 1.5 中那样，把每个问题写进一张表格：

| # | 问题 | WCAG 2.2 | 影响到谁 | 修复方法 |
| --- | --- | --- | --- | --- |
| 1 | 两张卡片上都有一个叫「Demo」的链接 | 2.4.4（以及 2.4.9） | 列出链接的屏幕阅读器用户 | 说明每个链接打开的是哪个项目 |

然后一行一行地把所有问题都修复。保留这张表格：它的简短版本应该放进你的「How I built this site」（我是怎样构建这个网站的）板块。

### 第 12 步：在设备上测试，并检查速度

像课程 1.4 那样测试，并在学习日志中保留一份测试记录：设备、浏览器、什么正常、什么不正常。

- 每个页面都在 320、390、768 和 1280 像素宽度下测试。
- 至少在一部真实的手机上测试，竖屏和横屏都要。
- 用手机上最大的文字大小测试。

然后检查速度。打开 **Network**（网络）面板，勾选 **Disable cache**（停用缓存），然后刷新。在面板底部，工具会显示页面一共下载了多少。在 **throttling**（网络节流）菜单中选择一种慢速连接（例如「Slow 4G」），再刷新一次：这就是你的页面在手机信号弱时给人的感觉。

Ana 的首页总共大约 27 KB，比手机摄像头拍的一张照片还小。如果你的首页大得多，通常的原因是图片太大：把它们缩小。

### 第 13 步：文档

每个仓库都需要一个 `README.md`：GitHub 最先显示的页面。在你的 `portfolio` 文件夹中创建一个：

```markdown
# Ana's portfolio

My web development portfolio: https://your-username.github.io/portfolio/

## What is in it
- Home page, with my Phase 1 projects
- A case study of the Riverside Community Centre website
- A small 3D gallery, with a plain list as the fallback

## Built with
HTML, CSS, a little JavaScript, and A-Frame for the 3D gallery. No build tools.

## Accessibility
I aim for WCAG 2.2 level AA. Tested with the keyboard, NVDA, VoiceOver,
axe DevTools, 200% zoom, and two phones.

## Run it on your computer
Download the repository and open index.html in a browser.

## Credits
Drawings by XR Camp, shared under CC0.
```

这份示例 README 依次说明了：作品集的网址；里面有什么；用什么构建的；无障碍目标和测试方式；怎样在自己的电脑上运行；以及署名。

文档是工作的一部分，不是额外的负担：下一个人，或者一年后的你，就是靠它来理解你构建了什么。

### 第 14 步：发布

像课程 1.8 那样，用 Git 和 GitHub Pages 发布：

1. 创建一个叫 `portfolio` 的仓库，把你的 `portfolio` 文件夹推送上去。
2. 在仓库的 **Settings**（设置）中打开 **Pages**，从你的主分支发布。
3. 几分钟后，你的作品集就在 `https://your-username.github.io/portfolio/` 上了。

在分享网址之前，检查已发布的网站，而不是你本地的副本：

- **每个链接都能用。** 链接必须是相对路径（`projects/riverside/index.html`），永远不要用你电脑上的路径（`C:\Users\...`）。
- **文件名完全一致。** 在大多数网页服务器上，包括 GitHub Pages，`Case-Study.html` 和 `case-study.html` 是不同的文件。所有地方都使用小写。
- **在手机上打开它**，用移动数据，而不只是用你的 Wi-Fi。
- **从隐私的角度再读一遍**，把第 6 步的表格放在旁边对照。

### 第 15 步：保持更新

作品集永远不会真正完成。在日历中设置一个每三个月一次的提醒，去做这些事：

- 添加你最新的项目，如果超过五个，就去掉最弱的那一个；
- 点击每一个链接，因为东西一移动，链接就会坏；
- 更新页脚中的「Last updated」（最后更新）日期；
- 重读你的「About」（关于我）板块：它还在描述你吗？

在 XR Camp 的每一个阶段，你都会往这个作品集里添加内容：第三阶段添加 3D 场景，第四阶段添加 XR。你是在为未来几年构建它，而不只是为了这节课。

## 关键代码解析

**`hidden` 和渐进增强。** `hidden` 属性会把一个元素从页面上和屏幕阅读器中移除。筛选器一开始是隐藏的，由脚本把它显示出来，所以页面永远不会显示不能用的控件。样式表中的 `[hidden] { display: none !important; }` 确保没有其他规则会误把隐藏的元素显示出来。

**`data-skills` 和 `dataset`。** 自定义数据属性把给脚本用的信息直接存放在元素本身上。`card.dataset.skills` 读取 `data-skills`；`.split(' ')` 把「responsive accessibility」变成一个数组。

**`<dl>`、`<dt>`、`<dd>`。** 描述列表：每个术语（`dt`）后面跟着它的描述（`dd`）。它是表示「My role」（我的角色）和「Time」（时间）这类关键信息的正确元素。

**`aria-current="page"`。** 告诉屏幕阅读器，哪个导航链接是当前所在的页面。样式表还会给它加下划线，所以它不只是靠颜色来标示。

**`mailto:`。** 一个会打开访客的邮件应用、并自动填好你的邮箱地址的链接。

**列表就是数据来源（在 3D 展厅中）。** 脚本从普通的 HTML 列表中读取项目，并为每个项目构建一块 3D 展板，所以 3D 展厅和它的后备方案永远不会不一致。

## 3D 时刻

打开 [`starter/gallery-3d.html`](starter/gallery-3d.html)。这是一个小小的展厅，墙上为每个项目挂着一块带框的展板。点击一块展板，或者使用 **Previous project**（上一个项目）和 **Next project**（下一个项目）按钮：被选中的展板会出现红色边框并向前移出一步，**Open**（打开）链接会变成指向那个项目，屏幕阅读器也会朗读当前选中的是哪一个。

在 TODO 12 中，把项目列表换成你自己的项目，然后更新场景描述，让它和你看到的内容一致。你不需要写任何 3D 代码：脚本会根据你的列表构建展板。

读一读这段脚本，注意其中四条规则，你会在 XR Camp 接下来的学习中一直遵守它们：

1. **2D 内容优先。** 普通列表才是真正的内容，它在每一种设备上都能用，无论是否支持 WebGL。3D 是根据它构建出来的。
2. **每一种 3D 交互都有键盘操作方式。** 同一个函数 `select`，既由点击展板调用，也由两个按钮调用。
3. **场景描述**（`id="scene-description"`）用文字说明场景中显示了什么。
4. **舒适。** 摄像机没有 `look-controls`，也没有 `wasd-controls`：视角永远不会移动，也没有东西会自己移动。被选中的展板会立刻换位置，而不是滑过去。

展厅放在单独的页面上，所以只有选择去访问它的人才会下载 A-Frame 库。每个 3D 页面都要做的人工检查，列在 [`docs/en/xr-accessibility.md`](../../docs/en/xr-accessibility.md) 中。

## 无障碍要求

| 要求 | WCAG 2.2 | 原因 |
| --- | --- | --- |
| 每个页面都有语言设置和描述性的标题 | 3.1.1、2.4.2 | 屏幕阅读器会使用正确的语音；标签页和搜索结果也清楚易懂。 |
| 标题、列表和地标都是真正的 HTML | 1.3.1 | 人们可以按标题跳转，并听到「列表，4 项」。 |
| 传达信息的图片有有意义的替代文本；重复的或装饰性的图片使用 `alt=""` | 1.1.1 | 屏幕阅读器用户能得到信息，又没有多余的干扰。 |
| 每个链接都说明它去哪里 | 2.4.4、2.4.9 | 要写「Visit the Riverside website」（访问 Riverside 网站），而不是四次「Demo」。A 级允许用链接周围的卡片来解释链接；AAA 级（2.4.9）要求链接文字单独出现时也能说得通，这对每个人都更友好。 |
| 文字对比度至少为 4.5:1；焦点轮廓和边框至少为 3:1 | 1.4.3、1.4.11 | 在阳光下和低视力情况下都能读清。 |
| 在 320 像素宽时不需要横向滚动 | 1.4.10 | 放大到 400% 的人，看到的就是一个 320 像素宽的页面。 |
| 所有功能都能用键盘操作，并且焦点可见 | 2.1.1、2.4.7 | 包括筛选器和 3D 展厅。 |
| 每个页面都使用同样顺序的同一套导航 | 3.2.3 | 人们只需要学一次。 |
| 筛选器的结果数量会被朗读 | 4.1.3 | 屏幕阅读器用户知道筛选起作用了。 |
| 3D 场景有文字描述 | 1.1.1 | 对屏幕阅读器来说，画布只是一个空白的矩形。 |
| 3D 场景中没有东西会自己移动，摄像机也永远不会移动 | 2.2.2 | 没有需要暂停的动态效果，也不会引起晕动症。 |
| 没有任何你不会告诉陌生人的个人信息 | 良好做法（不是 WCAG 规则） | 为了你和你家人的安全。 |

## 性能注意事项

作品集常常是在手机上被打开的，打开它的人会在几秒钟内决定要不要继续读下去。Ana 的首页，连同样式表、脚本和四张绘图，大约是 27 KB。对此最大的威胁是图片：一张原尺寸的截图，可能比其他所有东西加起来还重，所以要把截图缩小到大约 1000 像素宽，并像课程 1.4 中那样，对大图片使用 `srcset`。

A-Frame 大约有 1.3 MB 的代码（压缩后约 350 KB）。这就是为什么 3D 展厅有自己单独的页面：从不访问它的人，就永远不会下载它。展厅也没有使用任何图片作为纹理，只用了彩色的形状和文字，所以它加载很快，而且直接从文件打开也能正常使用。

## 常见错误

| 错误做法 | 会发生什么 | 正确做法 |
| --- | --- | --- |
| 只有截图，没有故事 | 别人看到了结果，却看不到你怎样思考 | 至少写一篇包含决策的案例研究 |
| 小项目太多 | 好项目被淹没了 | 选出你最好的三到五个 |
| 每张卡片上都是「Demo」和「Code」 | 一串听起来都一样的链接 | 链接文字要说出项目名称 |
| 你的家庭住址或私人电话 | 全世界任何人都能看到 | 一个专门用于作品集的电子邮箱地址 |
| 原尺寸的截图 | 页面在手机上很慢 | 缩小到大约 1000 像素宽 |
| 使用你电脑上的路径（`C:\Users\...`） | 发布后链接就坏了 | 使用相对路径，全部小写 |
| 把 3D 展厅放在首页上 | 每一位访客都要下载 A-Frame | 把 3D 放在单独的页面上，从首页链接过去 |
| 用形容词代替证据 | 「充满热情」对读者来说毫无意义 | 说出你做了什么，以及你是怎样测试的 |
| 从不更新 | 旧项目和坏链接 | 每三个月提醒一次 |

## 故障排查

**我的网站在电脑上能用，但 GitHub Pages 显示「404」。** 检查你的首页是否叫 `index.html`，全部小写，并且放在仓库的顶层。发布后，等几分钟再刷新。

**已发布的网站没有样式。** 你的 `<link>` 中的 `href` 和文件名不完全一致。对照一下大小写：在网上，`Styles.css` 和 `styles.css` 是不同的文件。

**项目筛选器没有出现。** 脚本没有运行时，本来就应该这样。打开控制台：检查 `<script>` 标签的 `src` 是否和 `portfolio.js` 一致，并查找红色的错误。

**3D 展厅是空的或者是灰色的。** A-Frame 需要从网上下载，所以检查你的网络连接。如果设备不支持 WebGL，场景就无法绘制：下面的项目列表仍然能用，这正是它存在的原因。

**展板上没有名字。** A-Frame 的文字也需要从网上下载字体。检查你的网络连接，以及控制台。

**某个颜色没有通过对比度检查。** 把文字颜色调暗，或者把背景调亮，每次调一点，直到达到 4.5:1。

## 标准聚焦

你的作品集用到了好几个组织制定的标准。HTML 元素，包括 `<dl>` 和 `hidden` 属性，来自 **HTML Living Standard**（HTML 现行标准，由 WHATWG 维护）。你的布局来自 **W3C CSS 工作组**编写的各个 CSS 模块。你的无障碍目标 **WCAG 2.2** 来自 W3C 的网页无障碍倡议（Web Accessibility Initiative），它还发布了关于编写无障碍声明的指南，就像你的「How I built this site」（我是怎样构建这个网站的）板块那样。就连 `mailto:` 链接也是一项标准：IETF 的 RFC 6068。
