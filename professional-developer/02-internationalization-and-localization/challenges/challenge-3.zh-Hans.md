# 挑战 3：探索

**进阶选做。** 约 90 分钟。

自动检测并警告那些超出容器空间的文字。

## 任务

1. 编写一个小函数 `checkOverflow(root = document)`，遍历 `root` 中每一个带有 `data-i18n` 的元素，检查 `element.scrollWidth > element.clientWidth` 或 `element.scrollHeight > element.clientHeight`（真正的溢出，而不只是文字换行）。
2. 在 `main.js` 里每次调用 `renderAll()` 之后调用它，对任何溢出的元素，用 `console.warn` 输出其键名和当前语言。
3. 打开伪本地化，并在开启状态下切换全部三种真实语言。修复你的新检查发现的任何溢出问题——通常是一个本该用 `flex-basis` 而不是 `min-width` 的地方，或者一个不该存在的 `white-space: nowrap`（参见 README 中的「文本膨胀安全布局」部分）。
4. 可选的进一步拓展：不只是发出警告，而是添加一个小型页面内面板（仅在伪本地化开启时显示），列出所有溢出的键，这样译者自己审查时就不需要打开浏览器控制台了。

## 为什么这很重要

没有人会在每次发布之前手动点开每种语言下的每一个字符串。作为测试套件或 CI 的一部分（这是课程 6.1 流水线的工作，不是本课的内容）运行一个自动化的溢出检查，才能在学习者看到之前，就捕获到译者写的更长的句子把某个按钮撑坏的问题。

## 完成标准

- [ ] `checkOverflow` 能正确标记出至少一个故意造成溢出的元素（临时缩小某个 `.hint` 的 `max-width` 来验证它确实有效）。
- [ ] 在真实的溢出问题都修复之后，它不再报告任何问题。
- [ ] 伪本地化加上这项检查，能发现一些仅靠肉眼看伪本地化本身并不明显的问题。
