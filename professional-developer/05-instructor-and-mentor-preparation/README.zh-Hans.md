# 讲师与导师准备

**Language / Idioma / 语言:** [English](README.md) · [Español](README.es.md) · [简体中文](README.zh-Hans.md)

**课程：** `professional-developer` · **课时：** `instructor-and-mentor-preparation-05` · **时长：** 约 8 小时 · 11 次学习，每次 45 分钟 · 每周 4 次，约 3 周

---

> 用 XR Camp 的格式写一节简短的课程，或者写一份导师计划，并为把它贡献回去做好准备。

---

## 学习目标

完成本项目后，你将能够：

1. 写出足够具体、可以被检验的学习目标，而不只是「感觉上」正确的目标。
2. 规划一节节 45 分钟的学习，每一节都以学习者能看到、能点击或能读回的东西收尾——绝不是一节只以「阅读关于 X 的内容」收尾的学习。
3. 撰写一个实例讲解，通过展示成品中真实、可运行的一部分并附上推理过程来教学。
4. 为无障碍、低带宽学习改编教学材料：字幕、通俗语言，以及下载后能离线使用的材料。
5. 描述一个包容、安全的学习空间需要什么，包括一份真实的行为准则，以及一种真实处理伤害事件的方式。
6. 给出具体而友善的反馈，针对作品而不是针对人，让一位初学者真的能据此行动。
7. 设计一个简单的指导结构：节奏、每次交流的形式，以及清晰的边界。
8. 解释一节完成的课程或一份导师计划如何变成对 XR Camp 的一次真实贡献。

## 先决条件

- **课程 6.4：职业发展与专业实践**——本课假定你已经能够清楚地写出关于自己真实工作的文字。
- 至少完成过 XR Camp 之前的一个阶段，这样你在自己动笔之前，已经亲身体验过以这种格式被教授的感觉。
- 本课不引入任何新的编程语言；用到的工具是写作、纯 HTML，以及——针对本课研究的示例——你在之前阶段已经用过的 A-Frame。

### 第 1 步：什么让一节课程或一份导师计划真正管用

你至今上过的每一节 XR Camp 课程都有两个习惯，现在轮到你自己动笔时，值得明确说出来。第一，它们的学习目标是可检验的：「放置一个形状并设置它的颜色」可以通过查看完成的作品来确认；「理解 3D」则不能。第二，每一次 45 分钟的学习都以可见的东西收尾——一个能运行的功能、一张填好的表格、一项通过的检查——而绝不只是「阅读关于 X 的内容」，因为一位初学者如果在 45 分钟结束时看不到任何进展，就没有办法判断这次学习是否有效。

### 第 2 步：选择你的路径，开始你的模板

`starter/lesson-template/` 是一份完整的空模板，与每一节真实 XR Camp 课程所用的确切文件夹结构一模一样：`README.md`、`project.json`、`starter/`、`completed/`、`challenges/`、`tests/checklist.md`。`starter/mentor-plan-template.md` 是一份单独的文档，包含一份导师计划所需的各个部分：学员和目标、交流结构、实例讲解、反馈、无障碍与低带宽指导、包容而安全的指导，以及结业。复制与你的选择相匹配的那一份，先填好它的元数据——一个标题、一个大致的时长估算；如果是课程，还要有一份 `project.json`，其中 `estimatedMinutes` 和 `schedule.sessions` 要相互一致，这与 [`.github/CONTRIBUTING.md`](../../.github/CONTRIBUTING.md)（英文）对本仓库中每一节真实课程强制要求的规则完全相同。

### 第 3 步：无障碍教学，用通俗语言和低带宽方式

写作的对象，是一位用第二或第三语言学习、网络速度慢到无法进行大型视频通话的初学者：短句子，一句话一个想法，任何术语第一次出现时都要附上通俗的解释。字幕之所以重要，原因和实例讲解一样——学习者永远不应该需要能正常工作的音频才能跟上进度，所以如果你的课程或计划用到了任何录制的讲解，它的文字版必须承载同样的内容，而不是它的摘要。你所指向的每一份材料，下载之后都必须能离线使用，这和本仓库自己对所有固定版本库的要求是同一条规则。

### 第 4 步：一个实例讲解，以及如果是课程，起始代码的 TODO（TODO 1-3、7）

一个实例讲解，是通过展示真实、能运行的代码，或一份真实、填好的文档，并附上推理过程来教学的——而不是一个没有任何解释的成品，也不是一段没有任何具体对象可以指向的解释。如果你写的是课程，你的起始文件需要按照学习者遇到它们的顺序，写上编号的 `// TODO n: <做什么以及为什么>` 注释，这是本仓库中每一节示范课程都使用的同一套约定；你的完成文件是同一份文件的完成版，如果它包含任何 3D 内容，还要加上 `id="scene-description"`、每一项交互的键盘路径，以及一个带暂停按钮的 `prefers-reduced-motion` 检查。Ana 的 `completed/example-lesson/` 在最小的规模上，展示了这一整套模式端到端地运作起来的样子。

### 第 5 步：包容而安全的学习空间

每一个 XR Camp 空间，包括你即将创建的这一个，都受 [`.github/CODE_OF_CONDUCT.md`](../../.github/CODE_OF_CONDUCT.md)（英文）约束：一个免受骚扰的环境、被期望和不可接受的行为、一个真实的举报地址，以及针对共享 3D 和 XR 空间的具体说明（尊重个人空间、不用空间音频进行骚扰、尊重其他参与者的舒适度设置）。你自己的课程或导师计划必须引用这份文档，而不是重新写一个更短的版本，并且必须用你自己的话说明，如果有人举报了伤害事件会发生什么：你不会自己去调查或解决它，而是要指明一个真实的、举报应该送达的地方。

### 第 6 步：给出反馈

具体而友善的反馈，会指出发生了什么、为什么重要，而不会把问题归咎到这个人身上：「这个标题在 320 像素宽度下溢出了容器」教会了一些东西；「你的布局坏了」什么也没教会。对做对了的地方给出反馈同样重要，也需要同样的具体性，这样学习者才能有意识地重复那些奏效的做法。直接练习一下：对 Ana 的 `completed/example-lesson/` 写一段真实的反馈，说出一处做得好的地方及其原因，以及如果这是你自己的课程，你会改动的一处地方。

### 第 7 步：指导结构

一段指导关系需要一个可预期的形式：一个双方都同意的节奏（Ana 的示例计划是每两周一次、每次 45 分钟的交流）、一种审阅真实作品而不是作品描述的交流结构，以及关于联系方式、时间安排、哪些事该由导师负责解决、哪些不该的清晰边界。即使你主要的成果是一节课程而不是一份导师计划，也要写这一部分：用两三句话说明，一位导师可能会如何把你的课程当作一段更长的指导关系中的一个实例讲解来使用。

### 第 8 步：拓展挑战、检查清单和本地无障碍检查（TODO 8-9）

写出你自己的三个拓展挑战——基础挑战必做，创意和探索选做——以及你自己的 `tests/checklist.md`，如果你的课程包含任何 3D 内容，末尾要有一节「3D 与 XR（人工检查）」。如果你的成果有一个 `completed/index.html`，在提交之前先跑一遍本地的 `pa11y` 检查，这正是本课程自身的规范对每一节课程的要求。

## 关键代码解析

- **可检验的目标。** 一个被表述为学习者在一个真实作品上执行的动作的目标（「放置一个形状并设置它的颜色」）可以通过查看完成的作品来验证；一个基于感受的目标（「理解 3D」）不能，它更适合放进一句概括性的话里。
- **`// TODO n: <做什么以及为什么>`。** 一种在本仓库每一个起始文件中共用的编号注释约定，这样学习者总能按照他们遇到每一步的确切顺序，既知道要构建什么，也知道为什么它重要。
- **`prefers-reduced-motion` 加一个暂停按钮。** 本课程一直要求的组合，用于任何带动画的内容：系统偏好设置默认状态，一个可见、带标签的控件则让学习者能随时朝任一方向覆盖它（WCAG 2.2.2、2.3.3）。
- **引用行为准则，而不是重新表述。** 链接到 `.github/CODE_OF_CONDUCT.md`，能保证只存在一个权威版本的规则；一节课程或一份导师计划如果悄悄写出自己更短的版本，就有可能与它逐渐脱节。
- **为你自己的模板选择写一份决策记录。** 用一句话说明你为什么选择了课程还是导师计划，这正是课程 6.3 用它的决策记录教过的同一个「简短地、书面地解释你的理由」的习惯的一个小实例。

## 无障碍要求

| 要求 | WCAG 2.2 | 原因 |
| --- | --- | --- |
| `starter/index.html` 和 `completed/index.html` 都声明了文档语言，并有一个清晰的 `<h1>` | 3.1.1、2.4.6 | 总览页面本身必须体现出它所教授的标准 |
| 任何用 `list-style: none` 设置样式的列表都保留 `role="list"` | 1.3.1 | 一旦没有了项目符号，Safari 会去掉列表隐含的语义，其他浏览器没有这个问题 |
| 每个链接的用途都能从它自己的文字中看清楚 | 2.4.4 | 「Ana's mentor plan」能告诉屏幕阅读器用户他们将得到什么；「click here」不能 |
| 每个链接和按钮的焦点都可见 | 2.4.7 | 键盘用户必须始终能看到自己所在的位置 |
| 颜色对比度处处达到 AA 级，包括任何示例场景中 | 1.4.3 | 同样适用于总览页面和 Ana 的 3D 示例 |
| 你或你课程的示例添加的任何 3D 页面，都要有 `id="scene-description"`、一条键盘路径、一次 `prefers-reduced-motion` 检查、一个 2D 后备方案和一个固定的相机 | 良好实践；参见 [`docs/en/xr-accessibility.md`](../../docs/en/xr-accessibility.md)（英文） | 自动化工具看不到 `<canvas>` 内部，所以 3D 内容需要和本仓库中每一节 3D 课程一样的人工检查 |

## 性能注意事项

本课自身的成果是文字、一个小型总览页面，以及一个微小的嵌套示例；这些都不算重。如果你自己的课程主题包含一个 3D 场景，就应用课程 3.6 已经教过的方法：先测量，再优化，并把任何数字表述为「在我的机器上」。

## 常见错误

| 错误 | 会发生什么 | 应该怎么做 |
| --- | --- | --- |
| 把目标写成一种感受（「理解无障碍」） | 没有人，包括你自己，能检验它是否达成 | 把它表述为一个可检验的动作（「为一次 3D 交互添加一条能用的键盘路径」） |
| 一次以「阅读关于 X 的内容」收尾的交流 | 初学者没有办法判断这次交流是否有效 | 让每一次交流都以可见的东西收尾：一个功能、一张填好的表格、一项通过的检查 |
| 用自己更短的话重新表述行为准则 | 这个重新表述会随时间与真正的版本逐渐脱节 | 直接链接到 `.github/CODE_OF_CONDUCT.md`，只在它之外补充你这节课或这份计划特别需要的内容 |
| 反馈指向的是人，而不是作品 | 学习者会变得防御，而不是获得信息 | 指出具体的那一行、那种行为或那个决定，以及它为什么重要 |
| 因为「这只是一对一」而在导师计划中跳过一处真实的行为准则引用 | 一旦问题恰好出在导师身上，学员没有任何明确的求助渠道 | 即便是在一对一的计划中，也要明确指出举报地址和升级处理步骤 |
| 构建一个没有 `#scene-description` 或键盘路径的 3D 实例讲解 | 它没能达到本仓库对其他每一节课程都要求的那个无障碍标准 | 以 `completed/example-lesson/` 为最低限度、可运行的模式来参照 |

## 故障排查

**我 `project.json` 里的 `schedule.sessions` 和 `estimatedMinutes` 对不上。** `sessions` 必须等于 `estimatedMinutes / sessionMinutes` 向上取整——这与 [`.github/CONTRIBUTING.md`](../../.github/CONTRIBUTING.md)（英文）对本仓库中每一节课程的要求相同。用其中一个重新推算另一个，同时也要更新 README 顶部的时长说明。

**我的 `pa11y` 检查在一个 `<form>` 上失败了。** 一个 `<form>` 元素需要一个提交按钮（pa11y 的 H32 规则）；如果你的控件只是在视觉上被分组、没有真正的提交动作，就改用 `<div>` 或 `<fieldset>`，而不是 `<form>`。

**Safari 把我的列表播报成纯文本，没有项目符号，也没有「list」角色。** 任何用 `list-style: none` 设置样式的 `<ul>` 或 `<ol>`，都需要一个明确的 `role="list"`；Chrome 和 Firefox 无论如何都会保留隐含的列表语义，这正是为什么这个缺口在只用一种浏览器测试时很容易被漏掉。

**我的 A-Frame 文字对于非英语标签显示不对。** A-Frame 默认的文字字体会丢失带重音符号的拉丁字符和所有中文字符。对于超出纯 ASCII 范围的任何内容，改用 HTML 叠加层或 canvas 绘制的标签，而不是 `<a-text>`——这和 `docs/en/xr-accessibility.md` 的实例讲解中使用的变通方法相同。

4. 学习日志问题：写这份材料的过程中——目标、无障碍工作、安全部分，还是反馈的措辞——哪一部分需要反复修改的次数最多？为什么？

## 值得认识的女性

**Camila Achutti** 是一位巴西计算机科学家，2010 年还在圣保罗大学数学与统计学研究所读本科时，就发起了「Mulheres na Computação」（「计算机领域中的女性」）博客。此后，她在 2015 年联合创办了科技教育公司 Mastertech，并于 2019 年创立了教育类非营利组织 SOMA。

## 标准聚焦

本课不引入新的 Web 标准；相反，它要求你在一个本仓库已经密切遵循的标准内部工作：由 W3C 无障碍指南工作组维护的 W3C 网页内容无障碍指南（WCAG）2.2。你自己课程或导师计划中提出的每一条无障碍要求，都应该引用那份规范中一个真实的成功标准编号——这正是本课程自第一阶段起，README 文件一直遵循的同一种规范，也值得你把它带入你以后在任何地方贡献的教学材料中，而不仅仅是这里。
