# 挑战 3：探索

**进阶选做。** 约 90 分钟。

为你的简历页面添加 `schema.org` 结构化数据，并检查它是否通过校验。

## 任务

1. 动手写代码之前，先完整通读一遍 [schema.org 的 `Person`](https://schema.org/Person)（英文）类型参考文档。
2. 在 `index.html` 的 `<head>` 中添加一个 `<script type="application/ld+json">` 代码块，把自己描述为一个 `Person`：至少包含 `name`、`jobTitle`、`email`，以及一份从你真实的技能表中提取出来的 `knowsAbout` 列表。
3. 保证每一个值都真实，并与页面上可见的内容一致；结构化数据如果和访客能看到的内容相矛盾，比完全没有结构化数据更糟糕。
4. 用一次 JSON 语法检查（任何 JSON 校验工具，或者你浏览器控制台里的 `JSON.parse`）来验证你的标记；如果你能访问到一个公开的、支持 schema.org 的校验工具，也用它验证一次。
5. 在你的日志里写两三句话，说明有了这些数据之后，搜索引擎或其他工具现在能对你的页面做到哪些之前做不到的事。

## 为什么这很重要

一份只有人类能读懂的简历，对于一次直接的私信来说没问题，但结构化数据能让其他软件——搜索引擎、职位匹配工具，或者你自己未来写的脚本——无需猜测就能理解页面上的事实。这和本课程一直在教的 `aria-*` 属性、语义化 HTML 是同一个思路：把含义明确地表达出来，只是这次是说给另一种读者听的。

## 完成标准

- [ ] `index.html` 的 `<head>` 中存在一个有效的 `application/ld+json` 代码块。
- [ ] 其中每一个值都真实，并且与页面上可见的内容一致。
- [ ] 这段 JSON 经过真实校验工具检查，语法有效。
