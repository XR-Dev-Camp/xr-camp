## 学习目标

完成本项目后，你将能够：

1. 把一份简历构建成一个无障碍的纯 HTML 页面，并配有自己的打印样式表，确保它打印或另存为 PDF 时都干净整洁。
2. 为一个真实项目撰写一份公开的案例分析，解释你的过程和取舍，而不只是最终成果。
3. 撰写一份类似 LinkedIn 的个人资料（标题、简介、经历、技能），可以直接粘贴进任何职业社交平台。
4. 准备一份作品集讲解脚本，以及一份可以向面试官提出的真实问题清单。
5. 找出寻找自由职业客户的切实可行的方式，并撰写一份简单、具体的提案。
6. 用一个带缓冲量的时间区间来估算项目工时，而不依赖一个你无法核实的市场价格。
7. 撰写一份基本的发票，并用适合客户所在国家的通用说法描述付款方式。
8. 用通俗的语言解释一份自由职业合同通常会涵盖的范围、付款条款、知识产权和素材授权——同时清楚认识到这并非法律建议。

### 第 1 步：什么是职业材料包

职业材料包是一组文档，让一个陌生人不需要先见到你本人，就能判断你的工作水平：一份概括一切的简历，一份深入解释某一个项目的案例分析，一份符合某个社交平台格式的个人资料，以及在有人感兴趣之后接下来那场对话的准备材料。本课中的每一份文档，都是从你在本课程中已经完成的工作构建而来——重点不是虚构一段职业生涯，而是把一段真实的职业生涯描述得足够清楚，让别人能够信任它。

### 第 2 步：你的无障碍简历（TODO 1-4）

`index.html` 是一个纯 HTML 页面，不是来自某个简历生成服务的模板：每一个标题、每一个列表、每一个链接都由你自己掌控，这也意味着它是否无障碍，同样由你掌控。按顺序构建：一个带有你姓名和职位说明的页眉，一张技能表，一条链接到你真正完成的作品（你第一阶段的作品集，以及虚拟文化展览）的项目时间线，以及一节教育背景和可接受工作时间的说明。

有两条规则贯穿始终：绝不要在这份共享的课程作业中放入真实的家庭住址、电话号码或个人真实邮箱——像 Ana 的作品集那样，使用一个虚构但看起来真实的地址；也绝不要列出一项你从未真正练习过的技能。一份诚实地低估了你的简历，远比一份被后续追问戳穿是夸大其词的简历风险要小得多。

```html
<ul class="contact-list" role="list">
  <li><a href="mailto:ana.builds@example.com">ana.builds@example.com</a></li>
  <li>Remote, based in a UTC-6 time zone</li>
</ul>
```

### 第 3 步：打印样式表（TODO 5）

一份只在屏幕上好看的简历，一旦有人打印它，或把它另存为 PDF 附加到邮件里，就会失败。`print.css` 是用 `media="print"` 加载的，所以它绝不会影响页面在浏览器标签页中的样子；它只在页面真正被打印时才会生效。

```html
<link rel="stylesheet" href="styles.css">
<link rel="stylesheet" href="print.css" media="print">
```

一份好的打印样式表，会移除任何在纸面上没用的东西（一个「Print this page」按钮，在页面已经打印出来之后就打印不出任何有用的东西了），把配色切换成白底黑字以节省墨水、保证对比度，并在链接文字旁边打印出它的目的地，因为纸面上的读者无法点击它：

```css
a[href^="http"]::after {
  content: " (" attr(href) ")";
}
```

### 第 4 步：虚拟展览的公开案例分析（TODO 6-7）

`case-study.html` 是写给一个陌生人看的，不是写给你自己看的。读它的人并没有在你搭建第三、四阶段展览的过程中在场，所以它需要说出一张截图本身说不出来的东西：你着手解决的问题、你的角色、你方法中真实的步骤（加载模型、测量并改进性能、加入 WebXR、检查无障碍性）、结果，以及——同样重要的——如果重来一次，你会做哪些不同的事。一份只罗列已完成功能的案例分析，读起来像一张产品介绍页；一份说出了真实取舍的案例分析，读起来才像一位专业人士的作品。

任何性能数字，都要按课程 3.6 教过你的方式来陈述：说「在我的机器上」，而不是说成一个普遍适用的结论。

### 第 5 步：一份类似 LinkedIn 的个人资料（TODO 8）

`linkedin-profile.md` 按照专业社交资料通常预期的结构撰写——标题、一段简短的「关于」文字、经历，以及技能列表——这样它可以适配你最终使用的任何真实平台，而不会被绑定在某一家公司的产品上。把标题控制在一行以内，说明你做什么、以及一件让你的工作与众不同的事，并保证每一项技能都是真实的。

### 第 6 步：面试准备（TODO 9）

`interview-prep.md` 分为两部分。**作品集讲解脚本**是一条简短的、经过排练的、走过你自己作品的路径：从你解决的问题开场，先展示无障碍的后备方案再展示炫酷的版本，用键盘演示一次交互，说出一个真实的取舍，最后说明你接下来会做什么。**向面试官提出的问题**和你的回答一样重要：它们能帮你判断一个职位是否真的适合你，对于远程职位而言，还包括团队是如何跨时区协作的。

### 第 7 步：自由职业基础知识（TODO 10-13）

`freelancing-basics.md` 涵盖了一位新晋自由职业者立刻会需要的四件事：寻找第一位客户的切实可行方式（从已经能看到你真实作品的人和组织开始）、一份说明清楚「包含什么、不包含什么」的简单提案模板、一种诚实的估算方式——用一个区间加一个缓冲量，而不是一个容易被猜中的单一数字，以及一份基本发票必须包含哪些内容。这份文档还涵盖了如何与不同时区的客户合作，包括拉丁美洲或中国大陆的客户：把会议时间、货币和付款方式都以书面形式确定下来，主动去问、而不是想当然地假设客户那一边的常规做法。这份文档中不会出现任何具体的价格、费用或收费标准；在这里写下一个数字只会过时，还可能在日后误导你。

### 第 8 步：合同概览（TODO 14）

`contract-overview.md` 用通俗的语言解释了几乎每一份自由职业合同都会涉及的四件事——范围、付款条款、知识产权和素材授权，并且在开头和这里都清楚地标明：**这不是法律建议，各国法律各不相同。** 它的作用是帮助你认识到一份真实合同应该涵盖哪些内容，并提出有见地的问题，而不是在真正涉及金钱或真正发生纠纷时，替代一位合格的专业人士。

## 关键代码解析

- **`media="print"`。** 一个 `<link>` 属性，告诉浏览器只在页面被打印或导出为 PDF 时才应用那份样式表，在屏幕上从不生效，这样一个 HTML 文件就能拥有两套干净的设计。
- **`::after` 中的 `content: attr(href)`。** 一种生成内容，读取元素自身的 `href` 属性，并把它打印在链接文字之后——只在打印时有用，因为屏幕阅读器已经用另一种方式播报了链接的目的地。
- **`break-inside: avoid`。** 一条打印规则，要求浏览器不要把简历中的某一条目——比如某一份工作经历——从中间分页断开。
- **一个区间加一个缓冲量。** 把一项任务的估算写成「6-9 小时」而不是「7 小时」，再额外加上大约 15%-25%，用来应对每个真实项目都会遇到的计划外情况，传达的是诚实的不确定性，而不是虚假的精确。
- **「这不是法律建议」。** 一句直白的声明，说明一份文档解释的是通行做法，而不是某个具体司法管辖区的法律，这样读者就知道，在真正依赖它做决定之前，应该先咨询一位合格的专业人士。

## 无障碍要求

| 要求 | WCAG 2.2 | 原因 |
| --- | --- | --- |
| 声明了文档语言 | 3.1.1 | 屏幕阅读器据此选择正确的发音和语音 |
| 每一节只有一个 `<h1>`，标题层级顺序合理 | 2.4.6、1.3.1 | 让屏幕阅读器用户能按标题浏览简历，就像视力正常的读者浏览时那样 |
| 每个链接的用途都能从文字或上下文中看清楚 | 2.4.4 | 「Case study: the virtual cultural exhibit」能告诉屏幕阅读器用户他们将得到什么；「click here」不能 |
| 用 `list-style: none` 设置样式的列表仍保留 `role="list"` | 1.3.1 | 一旦没有了项目符号，Safari 会去掉列表隐含的列表语义，其他浏览器没有这个问题 |
| 表头使用 `scope`，表格带有标题（caption） | 1.3.1 | 屏幕阅读器能播报出某一行属于哪个技能领域 |
| 每个链接和按钮的焦点都可见 | 2.4.7 | 键盘用户必须始终能看到自己所在的位置 |
| 颜色对比度达到 AA 级 | 1.4.3 | 每一个标题和正文文字都必须是可读的 |
| 内容在窄屏下也能无损重排 | 1.4.10 | 一份简历在手机上应该和在笔记本电脑上一样可读 |

## 性能注意事项

本课的交付物是文字，加上一份小型打印样式表：没有图片、没有 3D，只有为打印按钮写的寥寥几行 JavaScript。它全部的体积就是一份和本课程其他部分共享的样式表。这里没有需要为加载速度优化的东西；真正重要的纪律，是让每一份文档都足够简短，简短到一位很忙的招聘经理或客户真的会把它读完。

## 常见错误

| 错误 | 会发生什么 | 应该怎么做 |
| --- | --- | --- |
| 列出一项你从未真正练习过的技能 | 面试中的一个追问就会暴露这个漏洞 | 只列出你真正搭建过或使用过的东西 |
| 在共享的课程作业里放入真实的家庭住址、电话号码或个人邮箱 | 个人信息会出现在一个公开仓库里 | 使用一个虚构但看起来真实的联系方式，像 Ana 那样 |
| 把一个项目的估算写成一个固定的工时数字 | 第一个小小的意外就会让估算出错，看起来像一个没兑现的承诺 | 给出一个区间，并明确加上一个缓冲量 |
| 一份没有列出「不包含什么」的提案 | 项目会在没人同意的情况下悄悄膨胀，多出额外的工作 | 说明哪些内容不在范围之内，以及变更该如何处理 |
| 在一份共享文档里写出具体的价格、费用或「通常」的报价 | 这个数字会过时，或者在不同的市场里误导别人 | 描述方法和流程；把具体数字留到一次真实、私下的对话中再谈 |
| 没有事先询问，就假定客户的付款方式或时区习惯 | 付款失败，或者会议被安排在对某一方来说完全不合适的时间 | 明确地以书面形式，就货币、付款方式和会议时间达成一致 |

## 故障排查

**打印预览看起来完全没有样式。** 检查 `print.css` 是否用 `media="print"` 引入（而不是 `media="screen"`，或者根本没有 media 属性），并确认你触发的是真正的打印预览（Ctrl/Cmd+P），而不只是调整了窗口大小。

**Firefox 的打印预览和 Chrome 看起来不一样。** Firefox 的打印预览会打开一个独立的简化视图，带有自己的「更多设置」面板来调整边距和缩放；如果你想让页面使用 `print.css` 的纯白背景，而不是任何渗透进来的屏幕配色，检查一下「打印背景」选项是否已关闭。

**打印时链接的目的地没有出现。** 这条 `::after` 规则只匹配 `href` 以 `http` 或 `mailto:` 开头的链接；像 `case-study.html` 这样的相对链接，故意不打印出一个原始路径，因为一旦页面变成纸质版，这个路径就没有任何意义了。

**无障碍检查工具标记了一个列表。** 如果你添加了一个用 `list-style: none` 设置样式的 `<ul>`，却没有加上 `role="list"`，Safari 上的 VoiceOver 会把它当作没有任何列表语义的纯文本朗读出来；Chrome 和 Firefox 的屏幕阅读器支持没有这个缺口，这正是它容易在测试中被漏掉的原因。

## 值得认识的女性

**Sandra Cauffman** 在哥斯达黎加圣何塞的贫困中长大，后来成为一名哥斯达黎加电气工程师和物理学家。她于 1988 年加入 NASA，在长达 37 年的职业生涯中一路晋升到高层领导岗位：MAVEN 火星任务的副项目经理，NASA 地球科学部门的副主任（其中有 17 个月担任代理主任），后来又担任其天体物理学部门的副主任。她于 2025 年从 NASA 退休，专注于指导年轻人，尤其是女性和拉丁裔女性投身 STEM 领域。

一段跨越数十年、经历过好几种截然不同角色、最终又有意转向指导他人的职业生涯，正是本课这几份小小的文档所勾勒的那种长期专业实践的雏形：在每一个阶段都诚实地说出你的工作，好让下一个机会能够找到你。

## 标准聚焦

本课依托的是两项日常的 Web 标准，而不是单独一份规范。CSS 工作组的打印相关特性——`media` 属性的 `print` 值、`@page` 规则，以及 `break-inside` 这样的属性——是本课程一直在使用的同一套 CSS 的一部分，只是这次应用在了屏幕以外的另一种输出设备上。另外，schema.org（一套由 Google、微软、Yahoo 和 Yandex 共同维护、专为嵌入普通 HTML 而设计的共享词汇表）定义了像 `Person` 这样的类型，让搜索引擎或其他工具能够直接从像本课简历这样的页面里读取信息——这正是探索挑战所尝试的事。
