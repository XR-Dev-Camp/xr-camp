# 挑战 1：基础

**必做。** 约 45 分钟。

把你在 `standards-plan.md` 中计划好的规范议题，真正提交出去。

## 任务

1. 重新读一遍你在 `standards-plan.md` 第 4 节起草的议题标题和正文。
2. 在该仓库现有的议题中搜索是否已有接近重复的内容。如果找到了，就在那条议题下留言，而不是新开一个，并把这件事记录在你的计划里。
3. 如果这确实是一个全新的问题，就用 GitHub 的议题表单，在真实的仓库上提交这个议题。
4. 把这个议题的网址添加到 `standards-plan.md` 第 4 节；如果这也是你要记录的那次贡献，同时添加到 `contribution-record.md` 里。
5. 至少等待一天。无论收到什么回应，哪怕暂时还没有任何回应，都如实记录下来。

## 为什么这很重要

一份只停留在计划阶段的计划，教不会你任何关于标准实际是如何运作的东西。在一个真实仓库上提交一个真实的议题，面对可能会、也可能不会很快回应的真实维护者，是唯一能让你知道自己的议题到底写得够不够清楚的方法。

## 完成标准

- [ ] 提交之前你搜索过是否有重复议题。
- [ ] 一个真实的议题存在于一个真实的网址上，并且这个网址已经记录在你的计划里。
- [ ] 你至少回去查看过一次，并记录下发生了什么，哪怕答案是「目前还没有回应」。
