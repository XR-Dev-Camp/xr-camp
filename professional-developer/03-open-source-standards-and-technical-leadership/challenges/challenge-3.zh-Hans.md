# 挑战 3：探索

**进阶选做。** 约 90 分钟。

为一个更难、更有争议的选择撰写第二份决策记录，并让它接受一次真实的评审。

## 任务

1. 新增 `mini-project/decision-record-0002-<your-topic>.md`，使用和决策记录 0001 相同的四个标题（状态、背景、决定、后果）。
2. 为 `scene-description-lint`（或你在挑战 2 中改名后的项目）选一个真正有争议的选择：例如，它应该让构建失败还是只发出警告，它应该如何处理一个完全没有 canvas 的场景，或者它是否应该支持 A-Frame 较旧的 `<a-text>` 语法。
3. 撰写背景部分时，先公正地陈述你没有选择的那个选项最有力的论据，再解释你为什么选了另一个。
4. 请一位同学，或你所选社区组里的某个人，读一遍并留下一条评论。把他们的评论和你的回应都记录下来，哪怕你并没有因此改变自己的决定。

## 为什么这很重要

大多数真实的技术决定都是有争议的，而不是显而易见的。一份只为你已经选定的答案辩护的决策记录，比不上一份表明你理解了替代方案、却依然做出了选择的记录有力。真正的技术领导力，包括把决定写得足够清楚，让当时不认同你的人，多年后依然能理解你的推理过程。

## 完成标准

- [ ] `decision-record-0002-*.md` 已存在，使用相同的四个标题。
- [ ] 背景部分公正地陈述了被否决的替代方案最有力的论据。
- [ ] 记录了一位真实评审者的评论，以及你的回应。
