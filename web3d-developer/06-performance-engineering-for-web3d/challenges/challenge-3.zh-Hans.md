# 挑战 3：探索

**进阶选做。** 约 90 分钟。

在贴图压缩，或者合并与实例化的权衡取舍中，选一个方向做得更深入——用测量说话，而不是靠猜测。

## 任务

选择以下之一：

**A. 一次真正的 KTX2 转换。** 在本地进行（这不需要成为评分项目的一部分，因为它会添加一个本仓库并不需要的二进制素材文件），安装免费的 [KTX-Software](https://github.com/KhronosGroup/KTX-Software)（英文）工具，把你生成的某张色块画布导出为 PNG，再用 `basisu` 把它转换成一个 `.ktx2` 文件。在页面的一份草稿副本中，用 `KTX2Loader`（`js/textures.js` 中被注释掉的示例是你的起点）加载它，比较 `renderer.info.memory.textures` 报告的大小，以及它在磁盘上的文件大小，和原始 PNG 相比如何。把你测量到的结果写下来。

**B. 把合并与实例化的权衡取舍推向更深处。** 用一个合并后的几何体（就像地面那样），而不是三个 `InstancedMesh` 批次，为主展区的物品搭建第二个版本，并测量两个版本的 `renderer.info.render.calls`，以及点击「重建」所花费的时间。然后让某一种展台在点击时改变颜色，在两个版本中都试一试，看看哪一个让这件事变得容易，哪一个让它变得困难。写下对于一个每个展台都需要能够独立重新着色的大厅，你会选择哪种方案，以及为什么。

## 为什么这很重要

README 中给出的经验法则——「达到几十个就实例化」「当一个变换永远不需要独立变化时就合并」——是指导原则，而不是铁律。用你自己的机器和测量数据去检验其中一条，才能让一条经验法则真正变成你理解的东西，而不是你死记硬背的东西。

- [ ] 你能用一两句话说明你测量到了什么，以及这对「什么时候该选哪种技术」意味着什么。
