# 挑战 3：探索

**进阶选做。** 约 90 分钟。

对于拥有多个动画片段的模型，让学习者选择播放哪一个。

## 任务

1. 在浏览器控制台中，等狐狸加载完成后，打印 `app.items.find(i => i.data.id === 'fox').mixer._actions`（或者在 `loadModels()` 内部临时添加 `console.log(gltf.animations.map(c => c.name))`）。本项目已经下载的这个真实 `Fox.glb` 文件自带三个片段：`Survey`、`Walk` 和 `Run`，尽管 `loadModels()` 目前只播放 `gltf.animations[0]`。
2. 修改 `loadModels()`（或它调用的一个新函数），把一个模型拥有的每一个片段都保存在 `item` 对象上，而不只是第一个（例如 `item.clips = gltf.animations`）。
3. 当狐狸被选中时，在 `#selection-info`（或一个新元素）中显示一小组按钮，每个片段名称对应一个，点击时对选中的那个调用 `mixer.clipAction(clip).play()`。先停止上一个动作（`item.action.stop()`），或者在它们之间做交叉淡入淡出（`newAction.crossFadeFrom(item.action, 0.3)`），确保永远不会有两个片段同时驱动同一个骨骼。
4. 给这些按钮使用本项目在其他地方已经采用的同一种无障碍名称模式：「播放：Survey」、「播放：Walk」、「播放：Run」。
5. 和之前一样遵守暂停按钮和减少动态效果：无论当前选择的是哪个片段，在 `animating` 为 `false` 时都应该冻结。

## 为什么这很重要

一个真实的 glTF 模型往往会为同一个骨骼提供好几个动画片段——一个待机姿势、一段走路、一段奔跑、一次挥手——而一个真实的应用必须决定，或者让用户来决定，播放哪一个、什么时候播放。这个挑战是第一次安全地接触这个决定的小场所，为第 3.7 课的结业项目要求你为自己选择的真实内容做出这个决定做好准备。

## 完成标准

- [ ] 狐狸真实的三个片段（`Survey`、`Walk`、`Run`）都能从页面上访问到，而不仅仅是第一个。
- [ ] 选择一个不同的片段会停止或交叉淡出上一个，让模型看起来永远不会出错。
- [ ] 暂停和减少动态效果依然能冻结当前正在播放的任何片段。
