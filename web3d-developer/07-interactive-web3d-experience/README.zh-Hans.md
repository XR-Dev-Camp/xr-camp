## 学习目标

完成本项目后，你将能够：

1. 把好几节课的 three.js 代码（如果你走的是 A-Frame 路线，则是 A-Frame 代码）整合进一个打磨完善、看起来像正式发布产品的页面，而不需要重写已经能正常工作的部分。
2. 搭建一个信息面板，为被选中的 3D 物体打开正确的详情，包括一个已加载素材的署名和许可证信息。
3. 用具体数字陈述一个性能预算，并实时对照它检查一个场景，而不是仅凭猜测判断它「够不够快」。
4. 为一个 3D 场景保留一份 2D 版本：同样的信息，用文字表达，始终存在，而不仅仅是一个后备方案。
5. 撰写发布说明（一份 `CHANGELOG.md`），描述一个项目的某个版本实际发布了什么。
6. 对一个既有的 3D 场景，完成一次完整的无障碍检查：场景描述、键盘路径、减少动态效果，以及色彩对比度，一起检查，而不是逐项单独检查。
7. 在动手搭建之前先阅读一份项目说明和一份评分标准，并在提交之前用评分标准检查自己的成果。
8. 用你自己的话，解释你选择保留、修改或扩展的展览背后的权衡取舍。

### 第 1 步：阅读项目说明和评分标准

打开 [`starter/brief.md`](starter/brief.md)（英文）和 [`starter/rubric.md`](starter/rubric.md)（英文）。与之前的课程不同，这个毕业项目从一份项目说明开始：一份简短的文档，说明需要交付什么；以及一份评分标准，准确说明它将如何被检查。在编写任何代码之前先阅读两者，这本身就是本课要教授的技能的一部分——真实项目的项目说明就是这个样子的。

### 第 2 步：浏览起始代码

打开 `starter/js/exhibit.js`、`js/loader.js`、`js/describe.js` 和 `js/app.js`。这四个文件都已经完成，和[第 3.5 课](../05-threejs-interaction-assets-and-animation/completed/)相比没有任何改动：展台、两个 glTF 模型、射线检测选择，以及每个模型各自的 `AnimationMixer`。你在这个毕业项目中的工作只存在于 `js/main.js` 和 `index.html` 中。

### 第 3 步：信息面板容器（TODO 1）

在 `starter/index.html` 中，找到「3. Info panel」，添加一个容器元素，`id="info-panel"`，`role="status"`，并配有一段起始文字。`role="status"` 意味着面板内容变化时，屏幕阅读器会朗读它的新内容，学习者不需要自己把焦点移动到那里。

### 第 4 步：性能预算的标记结构（TODO 2）

在同一个文件中，找到「5. Performance budget」，添加带有 `#budget-calls` 和 `#budget-triangles` 的 `<dl>`，以及一个带 `role="status"` 的 `#budget-result` 段落。这些都是带有起始文字的普通元素；`js/main.js` 会把它们填满。

### 第 5 步：`renderInfoPanel()`（TODO 3）

在 `starter/js/main.js` 中，编写 `renderInfoPanel(item)`。传入 `null` 时，它显示一条「未选中任何内容」的消息。传入一个基本几何体展品时，它显示一个标题和它的材质构成。传入一个已加载的模型时，它还要显示这个模型的署名，以及指向其来源和许可证的链接——这些都是 `js/exhibit.js` 已经在 `data.credit` 和 `data.sourceUrl` 中携带的同样事实，只需读取一次，不需要重新打一遍。

### 第 6 步：把信息面板接入选择逻辑（TODO 4）

在 `selectItem()` 内部调用 `renderInfoPanel(app.getSelected())`。这一行代码把 TODO 3 中的函数，和目前每一种选中展品的方式——点击画布、点按画布，或者「选择」按钮——连接了起来，因为这三者都已经调用了 `selectItem()`。

### 第 7 步：性能预算检查（TODO 5）

添加一个 `BUDGET` 常量（`{ calls: 20, triangles: 25000 }`），并在 `updateStats()` 内部，把 `app.renderer.info.render.calls` 和 `.triangles` 与它进行比较。把实时数字和通过/未通过的说明文字写入第 4 步中的元素。这正是第 3.6 课用来证明资源释放有效的同一个 `renderer.info` 对象；在这里，它用来证明这个展览始终保持在一个明确陈述的预算之内。

### 第 8 步：重新加载时清空面板（TODO 6）

在「重新加载」按钮的点击处理函数内部，调用 `renderInfoPanel(null)`，同时清除「选择」按钮的 `aria-pressed` 状态。没有这一步，一次重新加载会让上一次选择的信息面板，继续显示在一个实际上已经没有任何东西被选中的展览旁边。

### 第 9 步：测量你自己的数字

在浏览器开发者工具中打开性能面板，同时直接读取 `app.renderer.info`（Stats 面板已经显示了它）。记录你在自己机器上看到的结果，并把这些数字写入下面「性能注意事项」的表格中，替换掉本课撰写时留下的数字。「在我的机器上」是报告一个性能数字的正确、诚实的方式——它会和学习者自己的设备不同，这是预期之中的，而不是一个 bug。

### 第 10 步：署名页面和 `ATTRIBUTION.md`

`completed/attribution.html` 是一个独立的页面，完整地为两个模型署名，与页面上的署名列表是分开的。为你自己的版本搭建同样的东西，并让 `ATTRIBUTION.md` 与它保持同步：同样的事实，用同样的文字，出现在两处地方，这样就没有人需要猜哪一份是最新的。

### 第 11 步：`CHANGELOG.md` 的 `1.0.0` 条目

在 `CHANGELOG.md` 中写一条 `1.0.0` 条目，描述你的毕业项目发布了什么：有什么新内容（信息面板、性能预算、署名页面），以及任何已知的局限性（例如，这个预算是在一台机器上测量的）。这正是 frontend-engineer/09 课教授的、关于一次发布的同样的纪律：在一条带日期的条目中说明发布了什么，而不是散落在没人会再去读的提交信息里。

### 第 12 步：一次无障碍检查

大声朗读一遍 `scene-description` 的文字。确认每一个实时区域（`role="status"`）在每次变化时恰好朗读一次，而不是每一个动画帧都朗读一次。确认标题层级没有断层（`h1` → `h2` → `h3`，没有跳过任何一级）。这一步把之前各节课分别教授的检查项汇集在一起；一个毕业项目，正是这些检查项必须同时都成立的地方。

## 关键代码解析

- **`renderInfoPanel(item)`** 用一个真正的面板，取代了之前课程中一行式的选择文字：一个标题，说明展品的名字，以及一段说明它材质构成或署名的文字。它读取的是 `js/exhibit.js` 已经导出的同一份 `ITEMS` 数据，所以这个面板永远不会说出场景本身没有展示的内容。
- **`BUDGET` 常量**把「这够快吗？」变成了一个带有明确数字的、非此即彼的问题，`updateStats()` 每次运行（每秒两次）都会检查它。先陈述一个预算再去测量，然后对照它比较，正是猜测的反面。
- **`#info-panel` 和 `#budget-result` 上的 `role="status"`** 是 ARIA 实时区域：屏幕阅读器会自动朗读它们的新内容。两者一开始都带有静态文字，所以在 JavaScript 运行之前，它们永远不会是空的。
- **`attribution.html`** 与页面上的署名列表分开存在，这样一个审阅者，或者以后复用你素材的学习者，就有一个清晰的页面可以查阅许可证信息，完全不需要运行这个展览。
- **`CHANGELOG.md`** 是一个普通的 Markdown 文件，不是数据库，也不是某个工具：发布说明是一种习惯，而不是一项功能，这一步教的正是这种习惯。
- **六个编号的 TODO 全部位于 `index.html` 和 `main.js` 中**，绝不在 `exhibit.js`、`loader.js`、`describe.js` 或 `app.js` 中。这种划分是刻意的：一个整合既有可用代码、而不是重写它的毕业项目，比每次都从零开始，是一项更贴近现实的技能。

## 3D 与 XR 无障碍

这个毕业项目自始至终都是 3D 的，延续着第 3.1-3.6 课的展览，所以这里的无障碍工作不是 2D 页面中的某一个环节——它就是整个页面。下面的每一项要求，都已经在之前某节 Web3D 开发者课程中教授过；这个毕业项目的任务，是确保在信息面板和性能预算都添加进来之后，它们依然全部成立。

- 场景描述会针对每一次相关的变化更新：选择、动画状态和相机重置（`js/describe.js`，原样复用自第 3.5 课）。
- 2D 版本（`#exhibit-list`）携带着和 3D 视图、信息面板同样的信息，所以没有任何事实只存在于画布内部。
- 每一个交互都有键盘路径：「选择」按钮、左转/右转、重置视角、暂停/继续，以及重新加载，没有一个需要指针。
- 减少动态效果得到遵守：`window.__reducedMotion` 会让动画一开始就是暂停状态，暂停按钮始终会说明它接下来会做什么。
- 相机绝不会自己移动；`controls.enableDamping` 只是让学习者已经发起的一次移动变得更平滑。

| --- | --- | --- |
| `#info-panel` 和 `#budget-result` 使用 `role="status"` | 4.1.3（状态消息） | 屏幕阅读器用户能听到信息面板打开、预算结果发生变化，而不需要移动焦点去查看。 |
| 每个按钮的无障碍名称都以它可见的文字开头（「选择：狐狸模型」） | 2.5.3（名称中包含标签） | 使用语音控制或屏幕阅读器的人，可以用自己看到的词语来激活一个按钮。 |
| 颜色不是超出预算的唯一信号 | 1.4.1（颜色的使用） | `#budget-result.over-budget` 同时改变背景和文字，而不仅仅是一块颜色。 |
| 每个控件上焦点都是可见的 | 2.4.7（焦点可见） | 本项目的 `:focus-visible` 轮廓，和之前课程相比没有改动，在添加新控件之后依然必须显示。 |
| 减少动态效果会停止所有动画 | 2.2.2（暂停、停止、隐藏） | 玉石的转动和每个模型自己的动画，在操作系统要求减少动效时都会以暂停状态启动。 |
| 用 `list-style: none` 设置样式的列表上带有 `role="list"` | 良好实践（否则 Safari 会丢失列表语义） | 2D 版本、「选择」按钮和署名列表，都会继续被朗读为列表。 |

## 性能注意事项

这个毕业项目陈述的预算，是在全部展品加载完成之后：**最多 20 次绘制调用和 25,000 个三角形。** 这些数字是在撰写本课时所使用的机器上测量的（一台中端笔记本电脑，Chrome，集成显卡），比参考答案实际达到的数字略留了一点余量——参见上面的第 9 步，了解如何测量你自己的数字并更新这张表格。

| 测量项 | 在我的机器上（参考答案） | 预算 |
| --- | --- | --- |
| 绘制调用数，全部五件展品加载完成 | 11 | 20 |
| 三角形数，全部五件展品加载完成 | 约 18,000 | 25,000 |
| 重新加载后内存中的几何体数 | 与重新加载前的数量一致 | 必须一致（证明资源已释放） |
| 重新加载后内存中的贴图数 | 与重新加载前的数量一致 | 必须一致（证明资源已释放） |
| 项目总大小（`assets/` + 代码） | 远低于 1 MB | 20 MB（项目预算） |

如果你自己的展览超出了这个预算，可以应用第 3.6 课中的某项技术（实例化、合并几何体、更小的贴图），或者提高 `BUDGET` 常量，并在 `CHANGELOG.md` 中说明原因——一个刻意调整过、并且被记录下来的预算，和一个从没人检查过的预算，是完全不同的两回事。

## 常见错误

| 错误 | 会发生什么 | 应该怎么做 |
| --- | --- | --- |
| 只在画布点击处理函数中调用 `renderInfoPanel()` | 用「选择」按钮选择（键盘路径）永远不会打开面板 | 在 `selectItem()` 内部调用一次，因为每一种选择路径都已经调用它 |
| 把预算数字硬编码进 HTML，而不是写在 `js/main.js` 中 | 实时数字停止更新，通过/未通过的文字也永远不会变化 | 把它们只写一次，放进 `BUDGET` 常量，再从那里读取 |
| 凭记忆分别撰写 `ATTRIBUTION.md` 和 `attribution.html` | 只要其中一个被编辑，两者就会开始产生分歧 | 把事实从 `js/exhibit.js` 的 `data.credit` 和 `data.sourceUrl` 中复制到两处 |
| 因为「还没有发布任何东西」而跳过 `CHANGELOG.md` | 这个毕业项目就没有任何记录说明它实际包含什么 | 一旦满足评分标准的八行要求，就撰写 `1.0.0` 条目，准确描述这一点 |
| 只测量一次性能，从来不在自己的机器上测量 | README 中的数字描述的是别人的电脑，而不是你的 | 自己重做一遍第 9 步，替换上面表格中的数字 |

## 故障排查

**即使完成了 TODO 3 和 TODO 4，信息面板也从不出现。** 检查 `index.html` 中是否存在 `#info-panel`，`id` 是否完全一致（TODO 1）——这里的一个拼写错误会静默失败，因为 `document.getElementById()` 只会返回 `null`，`renderInfoPanel()` 什么也不会做。

**预算数字永远显示 `0 / 20`。** `updateStats()` 是在一个 `setInterval` 上运行的，而不是只运行一次。确认这个定时器没有被意外清除，并且 TODO 2 中的元素在定时器第一次触发之前已经存在。

**Firefox：** 性能面板的标签布局和 Chrome 不同；在同一个开发者工具工具栏（F12）中寻找「Performance」。`renderer.info` 给出的数字在不同浏览器之间是一样的；只有开发者工具面板的呈现方式不同。

**Safari：** 任何使用 `list-style: none` 的列表都必须带有 `role="list"`，这正是之前课程教过的——否则 Safari 的 VoiceOver 会把这个列表朗读成纯文本。确认你在添加的任何新列表标记上都保留了它。

**重新加载后，展览列表出现了重复的条目。** `renderItemList()` 用的是 `replaceChildren()`，而不是 `append()`；如果某次创意挑战的修改把它改成了 `append()`，旧的条目就会和新的一起留在 DOM 里。

## 值得认识的女性

Anita Havele 是 Web3D 联盟的执行董事，该联盟是 X3D 背后的标准组织——X3D 是网络 3D 的 ISO/IEC 标准化格式，其 4.0 版本（2024 年 3 月发布）与 HTML5 集成，并支持 glTF，也就是这个毕业项目自己所用模型的同一种格式。她负责协调该联盟与 W3C、Khronos、OGC 和 ISO 的工作，并曾担任 ACM Web3D 2025 大会的总联合主席；她职业生涯的早期曾在通用汽车/EDS 从事工程标准方面的工作。

正如这个毕业项目要求你做的那样，发布一个打磨完善的 Web3D 体验，依赖于像 glTF 和 X3D 这样的标准在不同工具和浏览器之间保持互通——这类工作很少能引起学习者的注意，因为它成功的表现形式恰恰是「隐形」。Havele 的角色——协调一个标准组织与其他多个组织的工作——提醒我们「它就是能用」这件事，通常正是人们刻意让各种格式保持兼容所带来的结果。

## 标准聚焦

本课所用的模型是 glTF 2.0 文件，这是 Khronos Group 制定的、用于高效传输 3D 素材的标准，这里用 three.js 自己的 `GLTFLoader` 加载。更广泛的 Web3D 标准版图，还包括 W3C（负责管理 WebGL，并与 Khronos 一起负责 WebGPU）和 Web3D 联盟（负责管理 X3D，并与 Khronos 协调 glTF 相关事宜）。一个能在各种浏览器上「就是能用」的毕业项目，静静地依托于这三个组织在同一套格式上达成的一致。
