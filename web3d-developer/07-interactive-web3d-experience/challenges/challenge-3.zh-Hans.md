# 挑战 3：探索

**进阶选做。** 约 90 分钟。

添加第六件展品，使用这个毕业项目本身没有涉及的 three.js 技术，并测量它的成本。

## 任务

1. 用阶段 3 早期某项技术、而参考答案自己的展品并未使用的技术，添加一件新的展品——例如用第 3.6 课的 `THREE.LOD`，在远处切换成一个更简单的形状，或者用不同的 `AnimationAction` 混合权重播放第二条动画轨道。
2. 像另外五件展品一样，给它一个展台、一条信息面板记录，以及在场景描述和 2D 版本中的一席之地。
3. 用 `renderer.info`，在添加它前后分别测量它的成本（第 3.6 课的方法），并在 README 的性能表格中添加一行，展示「在我的机器上」的差异。
4. 如果这件新展品让绘制调用数或三角形数上升到足以威胁 20 次调用/25,000 个三角形的预算，就优化它（复用第 3.6 课的某项技术），或者在 `CHANGELOG.md` 中清楚说明提高预算的原因。

## 为什么这很重要

发布一个毕业项目，也意味着要对性能做出判断：不是每一个新功能都是免费的，一个专业的项目会陈述它的成本，而不是把它藏起来。这个挑战正是第 3.6 课教授的同一种纪律，应用到你自己搭建的东西上。

## 完成标准

- [ ] 存在第六件展品，完全接入了信息面板、场景描述和 2D 版本。
- [ ] 它测量出的成本以数字形式记录在 README 中，标注为「在我的机器上」。
- [ ] 性能预算检查依然正确地报告结果，无论这件展品是否在预算之内，还是预算被刻意提高并说明了原因。
