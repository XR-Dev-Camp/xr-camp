## 故事

### 从平面屏幕到空间

在历史上的大部分时间里，万维网都是平面的：一个矩形里的文字和图片。这并不是一种局限：正因如此，万维网才能在世界上每一部手机和每一台电脑上运行。但有些东西很难通过一张平面图片来理解：心脏的形状、一栋建筑的大小、一台机器的零件如何组装在一起。对于这些东西，万维网现在可以使用第三个维度了。

### 三种体验

- **2D 界面：** 页面、表单、列表、地图。速度快，人们熟悉，也最容易做到无障碍。
- **交互式 3D：** 普通页面中的一个 3D 场景，你可以用鼠标或手指转动它、探索它。你在课程 0.1 中已经构建过一个。
- **沉浸式体验：** 场景把你包围起来。你戴上头显走进其中，或者通过手机看到它被放在你的房间里。

### VR、AR 和 MR

- **虚拟现实（VR）** 用一个数字世界取代你眼前看到的一切。你戴上头显，周围的房间就消失了。
- **增强现实（AR）** 在真实世界中加入数字的东西：透过手机摄像头或眼镜，你会看到真实的桌子上放着一株虚拟的植物。
- **混合现实（MR）** 是一种 AR，其中的数字物体能够理解真实空间并作出反应：一个虚拟的球会从你真实的墙壁上弹回来。

**XR**（扩展现实）是这三者的统称；**WebXR** 则是一项万维网标准，让网页可以在支持它的浏览器中，通过一个链接、无需安装任何应用，就以上述任何一种方式打开。

### 空间计算、数字孪生和地图

- **空间计算**是指能够理解周围空间以及其中的人的计算机：墙在哪里，你的手在哪里，你在看哪里。
- **数字孪生**是某个真实事物（一栋建筑、一座工厂、一座城市）的实时数字副本，它会根据传感器的数据不断更新，让人们不必亲临现场就能检查情况或做出规划。
- **地理信息系统（GIS）** 存储并展示关于地点的数据：地图、道路、河流、洪水区。空间网络把这些地图与 3D 和 XR 结合在一起。

### AI 与空间网络

AI 正在开始像理解文字和图片一样理解 3D 空间：为看不见的人用文字描述一个场景，或者根据照片构建出 3D 模型。你将在第五阶段运用这些想法进行构建。

### 沉浸式在哪里有帮助，又在哪里没有

沉浸式体验在**空间、大小或临场感很重要**的地方最能发挥作用：安全地进行危险工作的培训，参观你无法亲身前往的博物馆或文化遗产地，了解人体解剖结构，在建筑建成之前就对它进行规划。

对于**读一读就能更快获取的信息**，例如营业时间、时刻表或表单，沉浸式体验就是错误的选择。它们还会消耗更多流量，需要性能更强的设备，可能引起晕动症，也更难做到无障碍。一位优秀的空间开发者知道什么时候*不*该使用 3D。

### 选择你的物体（TODO 2）

从你自己的生活或所在地区中，选择一样做成 3D 会很有意思的东西：一株玉米、一个陶罐、一丛茶树、一盏灯笼、一件乐器。用你在课程 0.1 中用过的那些简单形状（立方体、圆柱体、圆锥体、球体）来搭建它。

修改 3D 形状的颜色、大小和位置，让它们与你的物体相符。然后重写场景描述：看不见 3D 视图的人，也必须能够在脑海中想象出它的样子。

## 关键代码解析

**`<svg>`：用代码画成的图。** 2D 图画使用的是 SVG：由 `<rect>` 和 `<circle>` 这样带有位置和颜色的形状组成。`role="img"` 和 `<title>` 让屏幕阅读器把它当作一张图片，并附带文字替代内容。

**`<a-scene embedded>`。** 和课程 0.1 中一样，场景嵌在页面之中，而不是铺满整个页面。

**功能检测。** 脚本会先询问浏览器是否支持 VR 和 AR（`navigator.xr.isSessionSupported`），只有支持时才显示对应的按钮。绝不要显示一个无法使用的按钮。

## 无障碍要求

| 要求 | WCAG 2.2 | 原因 |
| --- | --- | --- |
| SVG 有文字替代内容 | 1.1.1 | 对看不见的人来说，一张图画需要用文字来表达。 |
| 3D 场景有与之相符的描述 | 1.1.1 | 同样的道理，适用于 3D 视图。 |
| 沉浸式按钮只在能用时才出现 | 良好实践（不是 WCAG 规则） | 不让人走进死胡同。 |
| 对比表格有标题和表头 | 1.3.1 | 每个单元格都保有它的含义。 |

## 性能注意事项

2D 视图只需要几 KB。3D 视图第一次打开时要下载 A-Frame（约 1.3 MB 的代码，经服务器压缩后约 350 KB）。这个差距正是本课的核心论点：你每增加一个维度，都会给你所服务的人带来成本。

## 常见错误

| 错误做法 | 会发生什么 | 正确做法 |
| --- | --- | --- |
| 因为看起来很炫而使用 3D | 页面更慢、更难用 | 只在形状或空间很重要时才使用 3D |
| 修改了 3D 场景却没有修改描述 | 屏幕阅读器用户得到的是错误的物体 | 修改场景时同时更新文字 |
| 把 AR 和 VR 搞混 | 讲解让人困惑 | VR 取代世界；AR 为世界添加内容 |

## 故障排查

**3D 视图是空的。** A-Frame 第一次需要从互联网下载。检查你的网络连接，然后刷新。

**没有出现 VR 或 AR 按钮。** 你的设备不支持它们，这在大多数电脑上都很正常。页面会告诉你这一点。试试挑战 3，用模拟器来测试。

## 标准聚焦

**WebXR** 由 W3C 的沉浸式网络工作组（Immersive Web Working Group）编写，因此同一个页面可以在不同公司生产的头显和手机上打开。在使用摄像头和传感器之前征求许可的规则，是这项标准本身的一部分，而不是事后才补上的。
