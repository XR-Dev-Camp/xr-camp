What happens when you visit a website

Nine steps, from typing an address to seeing a page. Most of them take less than a second. By Ana.

Reading the address

https://www.example.org/recipes/tamales?lang=es

https://: the scheme
How to talk to the server. The s means the conversation is encrypted.
www.example.org: the host, or domain name
Which computer to ask. People remember names; computers need numbers.
/recipes/tamales: the path
Which page on that computer.
?lang=es: the query
Extra information for the server, here the language.

The journey

  1. You and your browser

    1. You type an address

    You type www.example.org/recipes/tamales, or tap a link. The browser adds https:// if you did not.

  2. Your browser and DNS

    2. The name becomes a number

    Every computer on the internet has a numeric IP address. The browser asks the Domain Name System (DNS), the internet's address book, which number belongs to www.example.org. The answer is usually remembered for a while, so the next visit is faster.

  3. Your browser and the server

    3. A connection opens

    The browser connects to the server at that address. Because the address starts with https, they agree on a secret code first, so nobody in between can read or change what they send.

  4. Your browser

    4. The request

    The browser sends an HTTP request: GET /recipes/tamales, which means "please send me this page", plus details such as your preferred language.

  5. The server

    5. The server prepares the page

    A static site sends a file that already exists. A dynamic site builds the page on the spot, perhaps from a database: the same address can then show different content to different people.

  6. The server

    6. The response

    The server answers with a status code and the page. 200 means OK; 404 means not found; 500 means the server had a problem.

  7. Your browser

    7. The browser reads the HTML

    The browser reads the HTML from top to bottom and builds the structure of the page: headings, paragraphs, links, images.

  8. Your browser and the server

    8. More requests

    The HTML mentions other files: CSS for the look, JavaScript for behaviour, images, fonts. The browser requests each one, often dozens for a single page.

  9. You

    9. You see the page

    The browser draws the page on your screen, and runs the JavaScript that makes it interactive. You read, click, and the journey starts again.

In one sentence

The internet is the network that carries the messages; the web is the pages and links that travel across it; the browser is the client that asks, and the server is the computer that answers.
