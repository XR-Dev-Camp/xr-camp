# 挑战 3：探索

**进阶选做。** 约 60–90 分钟。

给 store 添加**撤销（Undo）**功能。

## 任务

1. 因为每一次改动都要经过三个动作，store 可以记住每次改动之前的状态。维护一个历史记录：在某个动作改变任何东西之前，把 `sessions` 的一份副本压入数组（`structuredClone(sessions)` 可以做深拷贝）。
2. 导出 `undo()`，它会恢复最近一份副本并调用 `commit()`。把历史记录限制在最近 20 次改动以内。
3. 在页面上添加一个**撤销**按钮，当没有可撤销的内容时禁用它。朗读被撤销的内容：「Undid: Deleted CSS grid.」。
4. 添加键盘支持：**Ctrl + Z**（Mac 上是 **⌘ + Z**），但当焦点在文本框中时不要触发，因为那里的 Ctrl+Z 已经用来撤销输入了。
5. 撤销之后，焦点应该去哪里？做出决定，并写下理由。

## 为什么这很重要

在旧计划器中，撤销功能几乎不可能实现，因为 `a` 随时可能被任何地方修改。而在新版本中，这只是一个很小的新增功能，因为进入状态的入口只有一个。这正是「状态只有一个归属之处」带来的好处，也是 Redux 这类框架能够实现撤销和时间旅行调试的原理。

## 完成标准

- [ ] 添加、完成、删除这三种操作都可以按顺序撤销。
- [ ] 没有可撤销内容时，撤销按钮处于禁用状态。
- [ ] Ctrl + Z / ⌘ + Z 有效，但在文本框内部除外。
- [ ] 每次撤销都会被朗读出来。
