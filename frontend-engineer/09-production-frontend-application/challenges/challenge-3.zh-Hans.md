# 挑战 3：探索

一个面向想要更进一步的学习者的可选进阶拓展。约 60–90 分钟。

## 任务

这个 3D 时刻目前只用一个形状属性（柱子的高度）编码了一个数字（已完成的课时数）。请为 `phaseProgress()` 返回的行数据中已经存在的信息，再添加**第二种**编码方式，使用第二个视觉属性——例如，用颜色的深浅来表示某个阶段接近完成的程度，或者在任何完成度达到 100% 的阶段上方加一个小标记。

规则：

- 不要在任何地方添加一条新的事实信息，如果它不是已经存在于 `phaseProgress()` 返回的行数据中的。
- `#scene-description` 也必须用文字描述这种新的编码方式，同样基于这份数据构建。
- 2D 孪生表格必须展示这种新编码方式所展示的相同信息。
- 摄像机保持固定，也没有任何动效，理由和之前一样。

然后，在你的学习日志中用一小段话解释这里的取舍：这第二种编码方式让人一眼就能更容易看清什么？它又需要付出什么代价（更多需要描述的内容、更多需要保持同步的东西、更多需要测试的地方）？

## 为什么这很重要

这正是 Redux 的「一个 store，多个视图」这类框架，以及各种可观察的数据可视化库所围绕构建的核心理念：真实的应用往往会随着时间推移长出更多针对同一份数据的视图，而不是数据本身的更多副本。在不改动数据的前提下添加第二个视图，并让每个视图都诚实地反映其他视图所展示的内容，正是这种纪律的一次小小演练。

- [ ] `#scene-description` 和孪生表格都反映了它。
- [ ] `tests/checklist.md` 中「3D 和 XR（手动）」部分依然通过。
