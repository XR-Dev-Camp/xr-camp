# 挑战 3：探索

**进阶选做。** 约 60–90 分钟。

设一个陷阱：向几个助手询问一个不存在的 API，看看哪些会告诉你真相。

## 任务

1. 安装一个本地模型运行工具，Ollama 或 LM Studio，下载一个较小的开放权重模型。先检查一下你是否有足够的可用磁盘空间：模型体积往往有好几个 GB。
2. 选择三个助手：这个本地模型，再加上两个云端服务（如果可以访问的话，至少有一个来自第 2 步中不同的分类）。
3. 向每一个助手提出同样一个**带有误导性的问题**，其中假设了某个不成立的前提：
   - 「删除一个条目后，我该如何用 `element.focusNext()` 来移动焦点？」
   - 「`Array.prototype.sort` 的 `copy` 选项有什么作用？」
4. 然后针对同一件事，再问一个**中立**的问题：「DOM 中有没有一个方法可以把焦点移动到下一个可获得焦点的元素上？」
5. 对每一个回答，记录下：它有没有说这个 API 不存在？它有没有编造出一个函数签名？它有没有转而建议一个真实存在的替代方案？把它建议的每一个真实 API 都拿去 MDN 上核实一遍。
6. 在正确性、速度，以及你不得不分享的内容这几个方面，比较一下本地模型和云端服务。

## 为什么这很重要

一个假设了错误前提的问题，往往会得到一个顺着这个前提给出的回答。了解这一点会改变你提问的方式：先问中立的问题，先问「这个东西存在吗？」，再问「我该怎么用它？」。运行一个本地模型，也能让你亲身体会隐私和质量之间的取舍。

## 完成标准

- [ ] 三个助手，包括一个本地模型，各自被问了同样两个带误导性的问题和一个中立的问题。
- [ ] 一张结果表：哪些编造了内容，哪些拒绝了回答，哪些纠正了你。
- [ ] 它们建议的每一个真实 API 都在 MDN 上核实过。
- [ ] 三句话，说明你下次提问时会做出什么不同的改变。
