The review, item by item

1. How || sorts by day, then time

What I asked
Explain the line with || in bySchedule, step by step, with an example. Do not rewrite the code.
What it said

If the days are different, the subtraction is not zero, so || returns it and the times are never compared. If the days are the same, it is 0, which counts as false, so || returns the time comparison instead.

What I checked
I predicted a positive number for Monday 19:00 against Monday 09:00. The Console gave 1, and check.html agrees.
Source
MDN: Logical OR, MDN: localeCompare()
Verdict
Accepted
What I learned
|| returns one of its values, not just true or false.

2. What subscribe returns

What I asked
What does subscribe return, and why would anyone want it?
What it said

A function that removes the listener again, for code that no longer needs updates.

What I checked
I subscribed a test listener from the Console with await import('./js/store.js'). It logged each new session. After stop(), it logged nothing, as I predicted.
Source
My Console test; MDN: Set.prototype.delete()
Verdict
Accepted
What I learned
The planner never calls it, because the page lasts as long as the planner. It is ready for the day part of the page can close.

3. "toggleSession crashes on an unknown id"

What I asked
Review store.js: possible bugs, security problems, and unclear code, each with how confident you are.
What it said

High confidence: if the id does not exist, find returns undefined and session.done throws a TypeError. Add a check.

What I checked
True in general. But every id comes from a list item drawn from the store a moment before, and I could not make it happen, even with two tabs open.
Source
MDN: Array.prototype.find(); reading main.js and session-item.js
Verdict
Rejected, for this code
What I learned
A finding can be true and still not matter here. My two-tab test found something else: two open tabs save over each other's changes. I noted it for later.

4. "XSS in announce"

What I asked
Is there any risk of cross-site scripting (XSS) in main.js?
What it said

Yes: announce puts the topic into the page with a template literal, so a topic like <img src=x onerror=alert(1)> would run.

What I checked
announce sets textContent. I added a session with that exact topic: no alert, and the text appeared exactly as typed.
Source
MDN: Node.textContent
Verdict
Rejected
What I learned
A template literal only builds a string. The danger is where the string goes: innerHTML reads it as HTML, textContent never does.

5. "Use toSorted"

What I asked
The same review of store.js.
What it said

getSessions can be shorter: return sessions.toSorted(bySchedule);

What I checked
It is real, and Baseline since July 2023. But older phones and browsers can run the planner and still not have it, and [...sessions].sort(bySchedule) does the same job everywhere.
Source
MDN: Array.prototype.toSorted()
Verdict
Rejected, for now
What I learned
Ask "does it exist?", and then "since when, and where?"

7. Is the form accessible?

What I asked
What does a screen-reader user hear when they submit an empty topic?
What it said

The form looks accessible. To be sure the error is read, add aria-live="assertive" to the error message.

What I checked
Keyboard only: everything worked. With NVDA and Firefox: pressing Enter inside the empty topic box read nothing new, because focus was already there. The error message is hidden until it has text, and MDN says a live region should exist before its content changes.
Source
MDN: ARIA live regions, WCAG 2.2: Understanding 4.1.3 Status Messages
Verdict
Changed: I kept the finding, not the fix. main.js now also sends the message to the planner's one status region, and NVDA reads it.
What I learned
The assistant read my code; it could not hear it.

Practice: invented APIs

A made-up "AI answer", written by XR Camp for practice, made four claims about the planner. I checked each on MDN and in the Console.

  • Wrong: getItem returns undefined for a missing key. It returns null (MDN: getItem()).
  • Invented: sort(compareFn, { copy: true }). sort has no options, sorts in place, and ignores the extra argument without an error (MDN: sort()).
  • Invented: element.focusNext(). No such method exists (MDN: focus()).
  • Correct: crypto.randomUUID() only works in secure contexts (MDN: randomUUID()).

What I learned

The assistant was best at explaining, and worst at knowing my code. The wrong claims sounded exactly as sure as the true ones, and I would have believed at least three of them without checking. I will keep using it the same way: small questions, explanations first, and a source for every claim.
