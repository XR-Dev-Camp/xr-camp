# Project check

Work through this list before you submit.

## Your repository
- [ ] Your own copy of the practice repository, public, with a study partner as collaborator (or "solo" noted in your log).
- [ ] GitHub Pages shows your study tips wall online (skip this if you work on Gitee, whose Pages service has stopped).
- [ ] Six issues, from `GOOD-FIRST-ISSUES.md`, with clear titles and labels.

## Pull requests
- [ ] Every change went through a branch and a pull request, never straight to `main`.
- [ ] Each pull request fills in the template and links its issue (`Fixes #…`).
- [ ] Each issue closed when its pull request was merged.
- [ ] You responded to review comments with new commits in the same branch.

## Reviews and conflicts
- [ ] You reviewed at least one pull request by someone else (or, solo, your own as a stranger would).
- [ ] Your reviews are specific, kind, and tested with the keyboard.
- [ ] You made a merge conflict, resolved it, and left no conflict markers.

## Release
- [ ] `CHANGELOG.md` has a 1.1.0 entry, written for the people who use the project.
- [ ] A `v1.1.0` tag and a published release.

## Accessibility
- [ ] The study tips wall has `lang="en"`, no typo, and small print with at least 4.5:1 contrast.

## 3D and XR (manual)

Automated tools cannot see inside a 3D canvas, so these are checked by a person. See [`docs/en/xr-accessibility.md`](../../../docs/en/xr-accessibility.md).

- [ ] The 3D example has a scene description naming every shape, left to right, and says what moves.
- [ ] With reduced motion on, nothing spins; the **Pause animation** button works with the keyboard and shows its state with `aria-pressed`.
- [ ] The camera never moves on its own.
