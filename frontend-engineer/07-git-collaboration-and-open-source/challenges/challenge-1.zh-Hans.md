# 挑战 1：基础

**必做。** 约 45 分钟。

成为一个更好的审查者。

## 任务

1. 审查三个拉取请求：你伙伴的一个，再加上另外两个（可以请同学帮忙，或者把自己以前的旧 PR 当作陌生人写的来审查）。
2. 在每一次审查中，至少要留下：一个问题、一条具体的修改建议（使用 **Insert a suggestion**），以及一条关于某处做得好的评论。
3. 批准之前先测试每一个 PR：打开该分支的页面版本，用键盘操作一遍。
4. 在你的练习仓库中写一份简短的指南 `REVIEWING.md`：列出五条关于友善、有用的审查的规则，每一条都配一个例子。通过拉取请求把它发送出去。

## 为什么这很重要

团队大部分的学习都发生在审查中，而且许多开发者审查的代码比他们自己写的还要多。审查得好——具体、友善、经过测试——是一项人们会注意到、也会记住的技能。

## 完成标准

- [ ] 三次审查，每一次都包含一个问题、一条建议和一句称赞。
- [ ] 你在批准之前测试了每一处改动。
- [ ] `REVIEWING.md` 已经通过一次拉取请求被合并。
