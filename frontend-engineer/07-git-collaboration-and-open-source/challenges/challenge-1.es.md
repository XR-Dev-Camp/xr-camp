# Reto 1: Fundamento

**Obligatorio.** Aproximadamente 45 minutos.

Conviértete en una mejor revisora.

## Tarea

1. Revisa tres pull requests: el de tu compañera, y dos más (pídeles a compañeras de clase, o revisa tus propios PR anteriores como si los hubiera escrito una desconocida).
2. En cada revisión, deja por lo menos: una pregunta, una sugerencia concreta (usa **Insert a suggestion**, insertar una sugerencia) y un comentario sobre algo bien hecho.
3. Prueba cada PR antes de aprobarlo: abre la página de esa rama, y úsala con el teclado.
4. Escribe una guía breve, `REVIEWING.md`, en tu repositorio de práctica: cinco reglas para revisiones amables y útiles, cada una con un ejemplo. Envíala como un pull request.

## Por qué esto importa

Los equipos aprenden más en las revisiones, y muchas desarrolladoras revisan más código del que escriben. Revisar bien —de forma específica, amable y probada— es una habilidad que la gente nota y recuerda.

## Se completa cuando

- [ ] Tres revisiones, cada una con una pregunta, una sugerencia y un elogio.
- [ ] Probaste cada cambio antes de aprobarlo.
- [ ] `REVIEWING.md` está fusionado, mediante un pull request.
