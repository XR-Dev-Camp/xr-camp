# 挑战 3：探索

**进阶选做。** 约 90 分钟。

把另一个 My XR Camp 应用也改造成 PWA，并比较它们各自的需求。

## 任务

1. 从你之前完成的应用中选一个：课程地图（课程 2.1）、学习仪表盘（课程 2.2），或者学习计划器（课程 2.3）。
2. 为它添加一份清单文件和图标、一个带有版本化缓存的预缓存外壳的 Service Worker，以及一个离线页面。复用你的 `pwa.js`：它应该不需要任何修改。如果需要修改，就不断改进它，直到不需要为止。
3. 为每一种请求决定一个策略，并在你的学习日志中用一张小表格记录下来：哪些文件、用什么策略，以及为什么。计划器把一切都保存在 `localStorage` 中，所以它可能完全不需要数据策略。课程地图会读取 `data/catalog.json`：这算是外壳（缓存优先）还是数据（网络优先，或过期重验证）？
4. 为其中一个尝试**过期重验证（stale-while-revalidate）**策略：立即从缓存中响应，然后在后台为下一次获取一份新的副本。在联网和 **Slow 4G** 状态下，比较一下它和网络优先策略的体验差异。
5. 为两个应用分别使用不同的缓存名称（比如 `planner-shell-v1`，而不是 `weather-shell-v1`），并检查每个应用的 `activate` 是否只删除自己的旧缓存。同一个源上的两个应用会共享同一套缓存。

## 为什么这很重要

一种策略就是关于每种请求哪个更重要的决定：速度、新鲜度，还是离线可用性。为两个不同的应用各做一次这样的决定，正是让你明白这里没有唯一的正确答案，只有每一个选择背后的理由。

## 完成标准

- [ ] 第二个应用能够安装，能够离线打开，并且对未保存的页面显示你的离线页面。
- [ ] 你的学习日志中有一张关于请求、策略和理由的表格。
- [ ] 你尝试过 stale-while-revalidate，并写下了一句关于它体验如何的话。
- [ ] 两个应用都不会删除对方的缓存。
