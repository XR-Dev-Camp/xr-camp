# 挑战 2：创意

**选做。** 约 45–60 分钟。

为一个来自你自己生活、文化或社区的小应用——而不是本课的应用——写出你自己的 STRIDE 风格威胁模型。

## 任务

1. 挑选一个你熟悉的小型真实（或贴近真实）应用：一个社区团体的报名表单、一个本地市场的订单聊天、一个学校的作业提交平台、一份变成了网页表单的邻里互助表格——任何带有账户、用户提交内容，或者某人个人数据的东西。
2. 为它写一张 STRIDE 表格，形式和本课 README 中的相同：每一类**S**（身份伪装）、**T**（篡改）、**R**（否认）、**I**（信息泄露）、**D**（拒绝服务）和 **E**（权限提升）威胁各占一行，每一行都指出*这个具体应用中*一件具体可能出错的事情——而不是那个类别的笼统描述。
3. 对其中至少三行，指出一个具体、现实的修复方式——在适用的地方引用一份 OWASP 速查表、一篇 MDN 文章，或者另一份一手资料，就像本课自己的 README 所做的那样。
4. 说明对你的应用来说，哪一个威胁如果不修复会造成最大的损害，并说明原因——谁会受到伤害，以及如何受到伤害。

## 为什么重要

STRIDE 是一种思考方式，而不是关于某一个具体代码库的事实——本课想让你保留下来的技能，是能对*任何*应用——包括你没有构建、也不会被打分的应用——具体地问出「这里可能会出什么问题」。为一件你自己在意的事情、用你自己的话做一次这样的练习，正是让这个习惯真正扎根的方式。

## 完成标准

- [ ] 一张针对你自己选择的应用的 STRIDE 表格，每一行都有一个具体（而非笼统）的威胁。
- [ ] 至少三行指出了一个具体、有出处的修复方式。
- [ ] 一段简短的说明，指出哪一个威胁对这个应用来说最重要，以及原因。
