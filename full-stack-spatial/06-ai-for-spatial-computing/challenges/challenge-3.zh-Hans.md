# 挑战 3：探索

**进阶选做。** 约 90 分钟。

通过 Ollama 或 LM Studio 接通一个真实的本地模型，并把它的输出和模拟服务商的输出做比较。

## 任务

1. 安装 [Ollama](https://ollama.com/) 或 [LM Studio](https://lmstudio.ai/)（两者都是免费的），按照它自己的文档下载并运行一个小型的通用聊天模型。确认这个工具的本地服务器正在运行，并记下它实际的端口——请查看该工具自己最新的文档，而不要想当然；本课程的 `.env.example` 列出了每个工具惯常的默认值，但任何一个项目都可能改变它。
2. 在 `server/.env` 中，把 `AI_PROVIDER` 设为 `local`，把 `AI_LOCAL_KIND` 设为与之匹配的 `ollama` 或 `lmstudio`，把 `AI_MODEL` 设为你拉取或加载的确切模型名称。重启服务器，检查 `GET /api/ai/status` 报告的是你的服务商和模型，而不是 `mock`。
3. 为两三个不同的已播种场景生成描述，并尝试两三次搜索。为每一次都记录下：
   - 这份回复是第一次尝试就被解析为有效的 JSON，还是这个项目的那一次重试（分步讲解的第 7 步和第 10 步）被触发了？
   - `checkDescriptionForHallucinations` 或 `filterMatchesAgainstRealScenes` 是否曾经不得不对模型说的某些内容发出警告或将其丢弃？
   - 措辞和模拟服务商那种更朴素、基于模板的句子相比如何——更自然，但也要注意：其中是否有任何一项说法，其实并不在你能在界面中看到的「Data sent」里？
4. 把你的发现写成一段简短的笔记（几句话就够了）——写在你的学习日志里，或者作为 `screenshots/` 下的一个新文件，如果你更想把它和你其他提交的证据放在一起的话。至少包含一个例子，说明本地模型的回复和模拟服务商针对同一个场景本会给出的回复有什么不同。
5. 在提交之前，把 `AI_PROVIDER` 改回 `mock`，这样任何审阅这个项目、但没有安装你的本地模型的人，依然能让它正常工作。

## 为什么重要

本课构建的每一项安全防护措施——只用 JSON 的指令、拒绝格式错误回复的解析器、幻觉检查、速率限制——都是针对一个从不出错的服务商（模拟服务商）设计和测试的。一个真实的模型，即使是一个小型本地模型，才是你能真正发现这些防护措施中哪些确实在起作用、哪些失败模式本课到目前为止都只是在一条注释中描述过的地方。

## 完成标准

- [ ] `AI_PROVIDER=local` 成功生成了至少一份真实的描述和一个真实的搜索结果。
- [ ] 你记录了重试路径、幻觉检查，或者搜索的幻觉防护，是否曾经真正针对一份真实的回复被触发。
- [ ] 存在一段简短的书面比较，对比了本地模型的输出和模拟服务商的输出，至少针对一个场景。
- [ ] 在提交之前，`.env` 已经改回 `AI_PROVIDER=mock`，并且没有任何地方提交了真实的密钥或特定于某个模型的机密信息。
