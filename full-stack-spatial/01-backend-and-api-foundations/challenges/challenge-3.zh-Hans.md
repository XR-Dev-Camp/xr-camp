# 挑战 3：探索

**进阶选做。** 约 90 分钟。

添加一份由服务器保存的设置历史记录，以及一个「撤销」路由。

## 任务

1. 在 `store.js` 中添加 `appendHistory(settings)`，把每一个被保存的设置对象（带上一个时间戳）作为一行 JSON，写入第二个文件 `data/history.jsonl`（「JSON Lines」格式：每行一个完整的 JSON 值，这样你就可以直接追加，而不需要重新读取或重新解析整个文件）。
2. 在 `routes.js` 的 `putSettings()` 中，在一次成功保存之后调用它，即使它出错，也不要拖慢或让响应失败（改为记录日志）。
3. 添加 `GET /api/settings/history`，以一个 JSON 数组的形式返回最近的 20 条记录（最新的排在最前面）。
4. 添加 `POST /api/settings/undo`：读取历史记录，恢复倒数第二条记录（也就是当前设置之前的那一条），把它保存为当前设置，并以 `200` 返回它。如果没有可以撤销到的内容，返回 `409 Conflict`。
5. 为这三种新行为都添加测试。

## 为什么重要

保留一份修改历史、并且能够撤销一次修改，是一个你以后会再次遇到的模式，一旦真正的用户可能会犯错（课程 5.3 针对已保存的场景，课程 5.5 针对安全事件）。在这里、在你自己这个由文件支撑的存储上做这件事，是一个能安全地体会这些权衡的地方：保留什么、保留多久，以及当两个人可能同时在编辑时，「撤销」到底应该意味着什么（课程 5.4 会再次回到这个问题）。

## 完成标准

- [ ] 每一次成功的 `PUT /api/settings` 都会向 `data/history.jsonl` 追加一行。
- [ ] `GET /api/settings/history` 返回的记录按最新排在最前面，并且从不超过 20 条。
- [ ] `POST /api/settings/undo` 能恢复上一次的设置，而连续第二次调用（此时没有更早的记录可以恢复）会返回 409，而不是崩溃。
- [ ] `node --test` 通过，包括针对这三个新路由的测试。
