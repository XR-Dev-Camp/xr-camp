# 挑战 2：创意

**选做。** 约 45–60 分钟。

让这个房间反映出你自己的语言、文化或社区。

## 任务

1. 把房间的名字从「main-hall」改成一个对你有意义的东西——你所在城市的一个地方，或者你自己语言中「聚会」「集合地」的一个词——同时更新 `server/rooms.js` 中的 `KNOWN_ROOMS` 和 `js/net.js` 中的房间字符串，使两者一致。保持底层机制（服务器上检查的一份允许列表）完全不变；只改变名字。
2. 给虚拟形象一个超越纯色的小小视觉身份：一种图案、一个来自你自己文化的手工艺或纺织传统的形状，或者一个对你个人特别有意义的配色方案（不是一个笼统的「好看的颜色」的选择——在一条注释中写明你*为什么*选择了它）。`js/scene.js` 的 `makeAvatarMesh` 是做这个改动的地方。
3. 添加一条系统聊天消息，在你加入时从客户端发送，用你自己的语言、以及英语一起问候这个房间——例如「你好！/ Hello!」——并在一条注释或你的学习日志中解释这句话的意思，以及你为什么选择了它。
4. 针对你的改动，重新运行 `tests/checklist.md` 中的无障碍检查项：一个新的虚拟形象形状或颜色依然需要通过对比度和动态效果检查，任何新文本也依然需要一个用简单语言写成的 2D 对应版本。

## 为什么重要

一个共享房间应该让人感觉像是某个具体的地方；一个通用的「Room 1」，配上一模一样的灰色虚拟形象，做不到这一点。一个名字、一个形状、一句问候语——这些小而刻意的选择，正是让一个工具感觉像是由一个真实社区、为一个真实社区打造出来的东西，而不是从一个模板拼装出来的原因。这对作品集来说也是一个好习惯：一张「练习原样如此」的截图，说明不了太多关于你的信息，一个明确、具体属于你自己的小改动却可以。

## 完成标准

- [ ] 这个房间的名字在它出现的每一个地方都已改变（服务器和客户端要保持一致，否则 WebSocket 升级会以 1008 关闭代码被拒绝）。
- [ ] 虚拟形象看起来和参考答案的纯色不同，并且这种不同是你能解释清楚的。
- [ ] 加入时会出现一句用你自己语言写的问候语，并且它依然能通过无障碍检查清单。
