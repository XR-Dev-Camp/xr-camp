                  Passkeys: a stronger sign-in this lesson does not build

                  A passkey replaces a password with a public/private key pair: your device proves who you are with the private key, which never leaves it, instead of you typing a secret a server must store and protect. That removes an entire category of the risk this lesson spends so much effort managing — there is no password hash to steal, and nothing to phish. Passkeys are built on the W3C's WebAuthn specification; see "Further reading" for the spec and an implementation guide. Building a passkey demo needs a public, HTTPS-served origin and a device with a passkey-capable browser, both outside what this localhost course can rely on, so this lesson explains the idea and stops there.

                  This is a learning prototype

                  This project is for learning, and it is deliberately small: one process, one machine, no shared session store, and an in-memory rate limiter that a restart clears. Before any part of this design protects a real account, real money, or real personal data, have it reviewed by someone with security expertise. Course 5.5 returns to this project to find and fix planted vulnerabilities.
